## 1. 背景与目标

本次改动基于 owner/admin 已有的三视图 checkbox、框选、全选和批量改派，补齐 member 在“待领取”的批量自领，并将卡片入口和选中反馈收敛到单一场景语义。

本改动已在不改变现有分工模型和媒体契约的前提下：

1. 为普通 member 和 `member + can_review` 增加仅限“待领取”的批量选择与批量领取；
2. 按视图精简卡片主操作，使“我的任务”负责进入标注、“待领取”负责领取、“全部”负责查看、独立预览与管理选择；
3. 保留全选入口但缩短可见标签，删除第二个选中勾，并保持现有选中边框、浅背景和无障碍反馈。

本文记录已实现契约和验收边界；独立精简验收已通过，当前已提交到本地 `feature/assignment-module`，尚未合并 `main`、推送或部署，人工浏览器矩阵尚未执行。

## 3. 固定的角色、视图与选择规则

### 3.1 选择能力矩阵

| 角色 | 我的任务 | 待领取 | 全部 |
|---|---|---|---|
| owner/admin | checkbox、全选、桌面框选；选择可改派的 `draft/rejected` | checkbox、全选、桌面框选；选择可分配的未分配 `draft` | checkbox、全选、桌面框选；选择可改派的 `draft/rejected` |
| member | 不启用批量选择 | checkbox、全选、桌面框选；选择未分配 `draft` 并批量领取 | 不启用批量选择 |
| `member + can_review` | 与普通 member 相同 | 与普通 member 相同 | 与普通 member 相同 |

`can_review` 只表示审核能力，不扩大负责人管理权限。member 的框选启用条件仅从“始终关闭”扩展为“当前视图是待领取且设备满足既有桌面框选条件”。

### 3.2 全选标签

全选控件不得删除。可见标签固定为以下短场景文案，完整语义放入 `aria-label`：

- owner/admin，“我的任务”或“全部”：**全选可改派视频**；
- owner/admin，“待领取”：**全选可分配视频**；
- member 或 `member + can_review`，“待领取”：**全选待领取视频**。

全选范围仍是当前视图、当前筛选和搜索结果中的可选视频；全选、半选、禁用及触屏点击目标沿用现有规则。member 的“我的任务”和“全部”不渲染该控件。

### 3.3 卡片选中与点击

- 删除 `.video-card.selected::after` 的第二个勾，只保留卡片左上角 checkbox 作为勾选标记。
- 保留 `.video-card.selected` 的边框和浅背景；保留 checkbox 与选择区域各自独立、清楚的 `focus-visible`，不能用删除伪元素为由削弱焦点反馈。
- 卡片空白区域只有在当前角色与视图支持选择、且该卡片可选时才执行现有单击/组合键选择；不支持选择时不响应选择。
- 卡片空白区域永远不用于导航。进入标注只能由明确按钮触发，避免“选择”和“进入视频”共用整个卡片点击区域。
- 桌面框选、组合键、中心命中、Esc 恢复、自动滚动、粗指针/`≤760px` 降级、pointer capture、临时 `user-select`、键盘、触屏目标及 `aria-live` 规则继续沿用[既有框选设计](../设计/视频列表待领取、框选与布局优化改动说明.md)，本文不重复其状态机细节。

## 4. 固定的卡片操作入口

| 视图 | 卡片操作 |
|---|---|
| 我的任务 | 显示“进入标注”；符合既有条件时可同时显示“释放”。 |
| 待领取 | 只显示“领取任务”；不显示“进入标注”或“释放”。 |
| 全部 | 不显示“进入标注”“领取任务”或“释放”，仅显示独立“预览视频”；未分工视频也可预览。owner/admin 仍可通过选择和批量栏管理负责人，预览按钮不得触发卡片选择或框选。 |

该规则对所有角色一致。上传完成后的独立“进入标注”回调不属于视频卡片入口，本改动不调整。

## 5. 批量领取后端契约

### 5.1 独立接口与 schema

- 新增 `POST /api/projects/{project_id}/videos/claims`，供任一 active 项目成员把一组可领取视频固定领取给自己的当前 `ProjectMembership`。
- 请求体固定为 `{ "video_ids": [...] }`，不接受 `assignee_membership_id` 或任何目标负责人字段。
- `video_ids` 必须包含 **1–200** 个唯一视频 ID。空数组、重复 ID、超过 200 个或不合法 ID 均由请求 schema 返回 422，不进入事务写入。
- 成功返回 200：`{ "claimed_count": N, "videos": [...] }`；`claimed_count` 等于请求 ID 数，`videos` 必须严格按请求顺序返回。

请求与响应类型已实现为 `VideoClaimsRequest`、`VideoClaimsResponse`，字段和校验遵循上述固定契约。

### 5.2 原子性与冲突

- 每个 ID 必须同时满足：视频属于路径中的项目、当前未分配、`workflow_status=draft`。
- 批量领取全有或全无。任一 ID 不存在、属于其他项目、已被领取或不是 `draft`，整个请求统一返回 409；不得通过不同错误泄漏跨项目或不存在视频的差异，也不得保留部分成功。
- 事务必须对全部请求 ID 做条件更新并核对更新数量；数量不等于请求数量时回滚整个事务。
- 两个请求包含重叠 ID 并发执行时，重叠范围至多一方成功；失败方返回 409，不能出现同一视频被两个 membership 成功领取或失败请求部分写入。
- 单个 claim 与批量 claim 复用内部 CAS helper，以统一“项目内、未分配、草稿、固定当前 membership”的条件和冲突转换。
- 该 helper 不得复用或扩展管理员 `POST .../videos/assignments` 的业务语义。管理员批量改派允许指定任意有效负责人、处理 `draft/rejected` 和清空负责人；批量领取不接受负责人字段、不允许 `rejected`、不允许清空。
- 既有单个 claim 的外部响应与 404/409 契约保持不变；共享 helper 不能把批量接口的防泄漏 409 反向套到单个接口。

## 6. 前端批量栏与结果处理

### 6.1 批量栏内容

- member 和 `member + can_review` 在“待领取”选择至少一个视频后，批量栏固定只显示：**已选 N 个**、**领取所选**、**取消选择**。
- member 批量栏不显示负责人 select，不出现“改派”“分配给”“清空负责人”等管理文案或能力。
- member 点击“领取所选”可使用简洁确认对话，内容只确认领取数量，不提供负责人选择。
- owner/admin 在“待领取”的批量栏标签使用**分配给**；在“我的任务”和“全部”使用**改派给**。其负责人 select、清空和既有管理员批量分配能力保持不变。

### 6.2 成功与冲突处理

- 单个或批量领取成功后均保持在“待领取”，刷新视频列表与 `claimable`，不自动跳到“我的任务”。
- 单个领取成功后从选择集中移除该视频 ID；其他仍可领取且仍可见的选择可保留。
- 批量领取成功后清空全部选择，并通过 `aria-live` 宣布成功数量。
- 批量接口返回 409 时，后端必须已全体回滚。前端刷新列表和 `claimable`，将选择集与刷新后仍可见、仍未分配且为 `draft` 的 ID 求交集：清理无效选择，保留仍可领取选择，并宣布冲突与剩余选择数量。
- 单个领取遇到 409 时采用同样的刷新与选择清理原则，不能无条件清空其他仍有效选择。
- 请求进行中禁用重复提交；失败后不显示部分成功数量。

## 9. 自动验收矩阵

| 层级 | 场景 | 必须断言 |
|---|---|---|
| schema | `video_ids=[]`、重复 ID、201 个 ID | 均返回 422，无数据库写入。 |
| schema | 请求包含 `assignee_membership_id` | 不接受该字段，不能借此指定他人。 |
| single claim | owner/admin/member/`member+can_review` 领取未分配草稿 | 保持既有成功响应，负责人固定为当前 membership。 |
| batch claim | 1、2、200 个合法 ID | 返回 200，`claimed_count` 正确，`videos` 与请求顺序一致，全部负责人为当前 membership。 |
| batch claim | 已领取或非 `draft` | 整体 409，所有请求视频均不变化。 |
| 防泄漏 | 缺失 ID、跨项目 ID、合法与非法 ID 混合 | 均统一 409，不区分原因、不部分成功。 |
| 并发 | 两个 membership 批量领取集合部分重叠 | 至多一个事务成功；失败事务无任何写入。 |
| 共用 helper | single 与 batch 分别遇到负责人/状态竞争 | CAS 条件一致；single 保持既有外部错误契约，batch 统一 409。 |
| 前端权限 | 角色 × 我的任务/待领取/全部 | owner/admin 三视图可选择；两种 member 仅待领取可选择。 |
| 前端入口 | 角色 × 三视图 | “进入标注”只在 mine；unassigned 只显示领取；all 仅显示独立原始视频预览。 |
