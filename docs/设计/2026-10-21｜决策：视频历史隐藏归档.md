# 2026-10-21｜决策：视频历史隐藏归档

> 类型：当前设计 + 详细记录
> 权威范围：视频后台失效终态、普通界面隐藏、写保护、新导出排除和只读候选定位
> 关联工作项：WI-20261021-01（由 orchestrator 登记）
> 历史状态：不在本文累积，见对应实验/决策/复盘记录

## 当前范围

后台可将明确视频的 `Video.workflow_status` 设为内部终态 `archived`。本实现只负责消费和保护该状态；没有浏览、恢复或管理 API，没有 apply 工具，没有执行实际归档，也没有访问或修改生产数据。

未来失效范围已确认是 19 个视频；本次只整合代码，不记录或执行生产数据更新。

归档只改变视频状态，不删除视频、人员关联、行为、提交、审核、片段或时长/帧区间。因此后续仍可按被标注视频时长核算工作量；工作量不是人工计时。

## 最小行为

- 普通视频列表过滤 `archived`。
- 审核队列和行为审核任务统计过滤 `archived`。
- 片段库列表和类别计数过滤 `archived`。
- `video_write_gate` 在写锁内重读视频并拒绝 `archived`，覆盖现有行为编辑、身份修正、抑制、检测导入落库、提交/撤回和审核写入。
- 距离标定是未经过共享门禁的直接视频写入口，因此在现有读取函数中补同一检查。
- 领取、释放、批量分配和硬删除原本只接受 `draft`/`rejected`，无需新增分支即可拒绝 `archived`。
- 新项目导出的候选查询排除 `archived`。任务冻结后、执行前再次查询相同冻结行为集合；来源后来变为 `archived` 时，现有集合完整性检查令任务失败，不生成 ZIP。
- 未归档视频/类别子集保持原导出行为。

共享拒绝响应沿用现有 FastAPI 形式：HTTP 409，detail 为 `该视频已归档，不能修改或导出`。该文案只服务后台/API 诊断，不要求前端增加功能。

## 刻意不做

- 不新增 schema、ORM 关系、迁移、依赖或全局 ORM 过滤。
- 不扩展 OpenAPI 或 `assignment-stats`，也不新增前端字段。
- 不改媒体生成/下载体系，不追溯已有成功 ZIP；需求只约束新导出。
- 不为后台运维、只读历史查询或每个不可达分支增加归档特判。
- 不实现恢复、批量管理、常驻归档 API 或一次性 apply；候选清单未确定前不扩大写面。

## 只读候选报告

`backend/scripts/report_history_archive.py` 是默认且唯一的 dry-run 路径：SQLite `mode=ro`，无 apply 参数。它只按 Project 2 中 `retired_reason = "Project 2 taxonomy migration"` 的 Clip 退役事件关联视频，不使用 1400 等数量阈值。

```powershell
python scripts/report_history_archive.py --db "<本地数据库副本绝对路径>"
```

报告输出视频 ID、文件名、现状态、duration、FPS、退役 Clip、非退役 Clip 数量、退役后新增/更新的行为及提交/审核证据，以及行为作者和帧/时间区间。存在后续证据时标为“混有后续数据”；没有证据也只标为“无法确定”，不会自动认定可归档。关联冲突、缺失或没有退役时间的事件进入 `unresolved_events`。

限制：数据库没有覆盖所有历史改动的统一审计时间；没有发现后续记录不等于证明不存在。脚本仅定位候选，不写数据库、不生成 apply 清单。
