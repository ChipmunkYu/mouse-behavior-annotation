> 类型：当前设计
> 权威范围：生产迁移、核心 API 契约与上传运行边界的本轮加固范围、验证证据和阶段结论
> 关联工作项：WI-20261014-01

## 范围

本轮保持 React SPA + FastAPI 模块化单体，不引入微服务、重型状态框架或新播放方案。仅处理：

1. 生产启动与显式数据库迁移的职责分离；
2. detection、identity edit、suppression 等核心接口的 OpenAPI 单一契约；
3. 上传同步磁盘 I/O 对单 worker 事件循环的阻塞，以及前端实际依赖的少量稳定错误码。

明确不修改当前完整认证 GET、下载进度、完整 Blob 和 object URL 播放方式。

## 实施原则

- 三阶段串行实施，每阶段聚焦测试、审查、记录和提交后再进入下一阶段。
- 保持现有 wire format、数据库内容、上传原子发布与失败清理语义。
- 只为可观察行为补测试，不机械扩大到全量测试。
- 本轮只做本地实现与验证，不部署标注服务器。

## 阶段记录

### 阶段 1：生产迁移边界

状态：已完成并通过 Oracle Gate 1。`ENV=production` 的应用、demo seed 与 retention cleanup 均在任何目录、engine、seed 或 worker 副作用前执行只读门禁，动态要求 Alembic 单一 head；缺失 SQLite、revision 不符或多 head 均失败并提示显式运行 `backend/scripts/migrate.py`。development/test 保持 fresh DB 自动迁移，显式迁移入口继续拥有 upgrade 职责，`--check` 仍只诊断。未新增绕过开关，`create_schema_app()` / `factory.py` 未改。

### 阶段 2：核心 API 契约

状态：已完成并通过 Oracle Gate 2。detections、corrected-tracks、corrected JSON export、identity check/apply/history/revert 与 suppression list/create/revert 均使用精确 Pydantic response model；前端对应 wrapper 绑定生成 operation，并删除镜像响应的手写 DTO，保留 `CorrectedTracksParams` 等 query/UI 类型。`deleteDistanceCalibration()` 现按既有后端 `VideoOut` 返回 `Promise<Video>`，调用行为不变。

兼容限制：identity preview/result 使用 `response_model_exclude_unset=True`，未产生的 `message`、`conflicts` 等字段继续缺失；split/merge preview 不新增 `affected_annotation_count`，前端移除该未定义展示；`keypoints` 仍为宽松 JSON，box 坐标用 `int | float` 保留原数值类型；无 active import 的 corrected export 仍为 404，不改不可达的 `result is None` 防御支路。未扩到 legacy/binary endpoint，未修改 media/playback/upload，未部署。

### 阶段 3：上传与错误边界

状态：子阶段 3A、3B 已完成。3A 新增最小共享上传 I/O helper，保留 `UploadFile.read(chunk_size)` 流式读取，将目录准备、逐块容量检查与写入、flush/fsync/close、空文件判断、同目录 replace 和失败清理移入 AnyIO worker；单视频、批次三类 slot 和检测替换复用该边界。取消路径捕获 `BaseException` 并 shield 清理已知 `.part` 和未归属 final；单视频仍以独立连接确认 DB 可见性决定文件所有权，proxy job 仍仅在确定提交后 submit。检测替换的大文件校验与两次流式 hash 合并移入 worker，并将预计算 hash 交给原同步插入函数；同步 batch complete 本来运行于线程池，保持不变。3B 为 release、batch assignment、owner/member 约束及视频删除 workflow/关联 job/cleanup 七类操作错误增加 `{code,message,context}`；原 HTTP status 与英文 message 不变，context 只含安全 ID、枚举和 boolean。异常源携带删除 code/context，router 仅序列化异常结构；前端保留 `ApiError.detail` 与旧 message 提取行为，仅按已知 code 映射，未知 code 和旧 string 继续原 fallback。

已知限制：同步 ORM 事务仍沿用现状；AnyIO 默认线程池负责背压，未引入自定义线程池、队列或新依赖；worker 内已开始的单次同步文件操作会完成后再响应取消。
