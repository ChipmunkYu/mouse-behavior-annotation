## 决策

标注 `POST/PATCH` 在持久化前对完整候选状态执行权威校验；失败返回普通 API 错误且不修改标注、修订或审核状态。提交服务使用同一权威规则防御性复验。门禁不新增数据库字段或迁移，也不依赖深度学习仓库运行。

参与对象规则完全由类别配置决定，不按行为名称或角色名称分支：

- `role_based` 的 `participant_roles` 必须恰好覆盖 `role_definitions`，每个角色满足自身 `min_count/max_count`；track ID 必须为非负整数、角色内唯一且不得跨角色，`mouse_ids` 为全部角色 ID 的去重升序并集。
- `unordered` 的 `participant_roles` 必须为空，`mouse_ids` 必须为严格非负整数（拒绝布尔值、负数及字符串/浮点数转换），数量满足类别 `mouse_count_min/max`。POST/PATCH 使用相同请求边界规则；无检测导入的非社交草稿仍可保存合法占位 ID，并保持 `needs_mouse_ids`，不代表具备提交资格。
- 因此 Attack 由现有 Attacker/Attacked 配置自然约束，不存在 Attack、Approach 或其他行为的硬编码特例。
- 数据库仍保留 `participant_status=needs_participants` 以兼容历史记录和检测修订后的状态表达；新建或编辑保存必须提交满足当前配置的完整参与对象。

## 社交行为连续性

连续性检查只适用于 `category.group == "社交行为"`。对每只已选参与小鼠，在行为正样本闭区间 `[start_frame,end_frame]` 内分别检查当前有效 identity、suppression 和 crop 视图：有效检测未被 crop 排除，且 `neck/base_of_neck/left_hip/right_hip` 至少一个中心关键点坐标有限时，该帧才可供下游使用。

- 每只参与小鼠至少有一个可用帧。
- 连续缺失 `1–5` 帧仅按长度允许，包括边界缺失、参与者同时缺失以及不满足转换器插值条件的短缺口。
- 连续缺失 `6` 帧及以上硬拒绝；错误包含 track ID、缺失起止帧和帧数。
- 非社交类别不执行该连续性检查。

转换器自身仍不会因长缺口直接报错；本门禁是网站保存侧新增的数据质量规则，不应描述成转换器既有约束。

同 track 同帧重复检测按导出顺序处理：先跳过 `transform_detection` 返回 `None` 的记录（包括完全被 crop 排除），再由最后一条实际导出的检测决定中心可用性。后条实际导出但中心无效仍覆盖前条可用状态。

## 前端与实现边界

前端没有持久化 blocker 字段或独立问题面板。保存失败沿用普通 API 错误详情展示，下一次保存尝试或成功后清除陈旧错误。审核反馈模型、播放器和提交失败结构不变。

当前实现集中在 `backend/app/participant_continuity.py`、标注写入路由和提交服务；无行为名称白名单、无角色名称特判、无 migration，未部署。
