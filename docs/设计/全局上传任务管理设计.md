# 全局上传任务管理设计

> 状态：已实现；浏览器人工矩阵待验收
>
> 实现分支：`feature/persistent-upload-manager`

## 1. 目标与适用边界

本功能面向不超过 6 人的小规模协作，常见同时上传者为 1–2 人。上传执行生命周期从视频库上传面板提升到登录后的全局布局，使任务在同一浏览器标签页、同一 SPA 会话内跨页面继续运行；关闭上传面板或在项目、视频库、标注、审核、片段库等路由之间切换均不取消任务。

本实现不是 Service Worker 或服务端“上传后台任务”，不支持刷新/关闭标签页后的恢复、跨设备恢复、分片上传或按字节断点续传。浏览器持有的 `File`、XHR 和任务状态只存在于当前 SPA 会话。

## 2. 已实现方案

### 2.1 全局管理器与上传任务栏

- `UploadManagerProvider` 挂载于登录后的 `AppLayout`，统一持有单视频和三文件导入批次任务、任务级 `AbortController`、进度、错误及服务端 `batchId`。
- 全局最多同时执行 2 个上传任务，与生产代理每客户端 IP 2 条上传连接的约束一致；排队任务按加入顺序调度。
- 任务可来自不同项目。常驻上传任务栏展示文件或批次名、项目、具体阶段、真实总进度、错误和取消清理状态，且每个任务的取消、重试和进度互不影响。首个及后续新任务入队时自动展开，即使用户此前手动收起也会对新任务展开一次；顶栏入口持续显示活跃/失败数量并可重新展开。桌面固定右下，窄屏为底部全宽可滚动区域，列表限制最大高度。
- `VideoUploadPanel` 只负责选择文件、当前负责人和创建任务，不再拥有上传请求生命周期。任务成功后递增对应项目的刷新版本，当前项目视频库据此刷新。

### 2.2 单视频与三文件顺序

- 单视频任务继续调用现有 multipart 上传接口，并由 XHR 提供真实字节进度和取消能力。
- 三文件导入批次固定按 `tracks → metadata → video` 顺序上传，再调用 `complete`。总进度按三个文件总字节计算；完成阶段显示“校验处理中”，不伪造服务端处理百分比。
- 每个批次任务独占自己的 `batchId`，不会把槽位、错误或完成请求写入其他任务。

### 2.3 终态与生命周期

- **取消即清理**：排队或运行中的单视频任务立即中止并从上传任务栏移除；三文件任务中止当前 XHR 后调用受保护的批次 `DELETE`，上传任务栏显示取消清理状态，并清理未消费文件、可安全删除的批次创建视频和批次记录。清理失败则保留失败任务供用户再次取消。
- **成功手动确认**：成功任务保留在上传任务栏，用户单项确认或“一键确认成功”后移除。
- **失败重试/取消**：单视频失败后可重新上传；批次失败重试前先查询服务端状态，已完成则转为成功，否则删除旧批次并从新批次完整重传。用户也可直接取消并清理。
- **退出清理**：正常退出登录先中止所有本地请求，并尽力删除所有未完成服务端批次，再清空登录态。
- **401 兜底**：认证失效时前端只能立即停止并清空本地任务，无法再调用受保护的删除接口；后端生命周期清理按 `updated_at` 回收超过 24 小时未活动的 `uploading/failed` 批次。

### 2.4 后端权限与清理边界

- 迁移 `0014_import_batch_ownership_activity.py` 为三文件导入批次增加可空 `created_by` 和非空 `updated_at`；创建、槽位活动、完成和失败路径更新活动时间。
- 批次创建者可读写、完成和删除自己的批次；项目所有者/管理员可管理项目内批次。其他普通成员不能访问别人的批次。
- `DELETE /api/projects/{project_id}/video-import-batches/{batch_id}` 仅处理 `uploading/failed`，并通过状态门禁、路径边界、引用检查和条件删除避免清理已消费数据。
- 清理语义是安全优先而不是严格 exactly-once。单视频接口没有幂等键；若服务端已提交成功而客户端只收到网络错误，重试仍可能产生重复视频。批次 complete 遇到网络结果不明时会先查询批次状态，降低普通网络抖动下的重复风险。
- 极端应用进程崩溃、文件系统与数据库提交窗口异常或持续清理冲突仍需运维检查 `cleanup-issues.log`、数据库记录和存储文件；本轮不引入多进程恢复或断点恢复机制。

## 3. 验收边界

本轮自动化证据：前端 production build 通过并处理 **66 modules**；后端上传、批次清理与迁移相关测试为 **128 passed, 3 skipped, 1 warning**。Oracle 结论仅为普通 1–2 人上传场景未发现阻断问题，不代表浏览器人工验收已完成。
