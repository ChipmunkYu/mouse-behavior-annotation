# 审核工作台行为导航、筛选、统计与颜色设计

> 状态：已实现（需求已确认；纯前端）
>
> 范围：`frontend/src/pages/ReviewPage.tsx`、审核视角下的共用 `Timeline`
>
> 数据基线：审核队列内联的 `submission_annotations` 是当前被审 Submission 的完整不可变行为标注快照；类别接口只补充展示颜色，不改变快照语义。

## 1. 目标

让审核者在不离开当前视频的情况下完成四件事：快速了解行为构成、组合聚焦多个行为类别、从行为列表定位到对应时刻，并用一致颜色关联统计、列表与时间轴。

设计遵循现有审核工作台的紧凑桌面信息架构，不增加后端请求范围、分页或新的页面层级。

## 2. 已确认需求边界

1. 点击**行为列表中的行为标注项**，播放器直接定位到该行为标注的开始时间。
2. 审核者可以组合筛选一个或多个行为类别。
3. 审核阶段即可看见当前视频中各行为类别的行为标注数量。
4. 时间轴标注区间颜色与行为类别颜色对应。
5. 不增加“点击时间轴标注区间后跳到该区间起点”的交互；时间轴仅保留现有按点击位置 seek 的整体滑杆行为。

## 3. 数据与展示口径

### 3.1 审核权威数据

- 列表、统计、筛选选项和时间轴均以当前视频的 `submission_annotations` 为唯一行为数据源，不读取当前 draft `Annotation`。
- 行为名称、分组、区间、参与对象和角色均使用 Submission 快照字段。即使当前类别接口返回了同 ID 的不同文案，也不得覆盖快照名称或分组。
- 统计单位是“行为标注条数”，不是持续时长、视频片段数量、参与对象数量或去重行为次数。
- 总数和各类别数量始终统计完整快照，不随当前筛选变化，避免筛选后把“当前显示数”误解为视频真实总量。

### 3.2 颜色来源

- `submission_annotations` 没有颜色字段。页面加载项目当前锁定类别方案的 `listCategories(projectId)`，仅按 `category_id` 合并 `color` 作为展示元数据。
- 快照名称和分组保持权威；当前类别仅提供颜色与可选的 `sort_order`。
- `color` 为 `null`、空值、非法 CSS 颜色，或快照类别 ID 在当前类别列表中缺失时，统一使用中性灰 `var(--text-3)`。
- 类别接口返回 409、网络失败或其他错误时，审核数据仍正常展示和裁决；统计、筛选、列表和时间轴全部灰色回退，并显示一条非阻断的弱提示“类别颜色暂不可用，已使用灰色显示”。不得把颜色失败并入审核数据加载失败，也不得禁用通过/退回。
- 颜色只作辅助识别。类别名称和数量必须始终可见，不能只凭颜色传递信息。

## 4. 已确认实现方案

### 4.1 页面布局

沿用“左侧审核队列 + 右侧当前视频”的主结构。右侧从上到下调整为：

1. 播放器、播放控制和时间轴；
2. **行为概览与筛选条**；
3. 行为标注列表 + 审核历史/审核意见；
4. 视频片段生成。

将“视频片段生成”移到审核操作区域之后。它是裁决后的结果状态，不应隔开播放器与审核所需的行为列表。审核通过后仍保留当前视频详情，用户可继续向下查看生成进度。

行为概览与筛选条紧贴时间轴，使用现有卡片、中性色和圆角，不创建新的侧栏或弹窗：

```text
行为概览   共 18 条 · 5 类
[全部 18] [■ 攻击 6] [■ 追逐 4] [■ 理毛 3] [■ 其他 5]
```

- “全部”是默认选项；其余选项由快照中实际出现的类别生成，不展示当前视频中计数为 0 的类别。
- 每个类别项同时承担“统计”和“多选筛选”两种职责，避免再增加一个下拉框或第二套控件。
- 优先按当前类别方案 `sort_order` 排列；无法匹配当前类别的快照项按其在快照中的首次出现顺序追加。
- 选中项使用现有强调色边框和浅强调色背景；类别色仅用于前置色块，不用类别色铺满按钮，以保证文字对比度。

### 4.2 筛选作用域

筛选按 `category_id` 集合取并集，并在以下区域同步生效：

- 行为标注列表只显示已选类别的行为标注；
- 时间轴只显示已选类别的标注区间；
- 播放器检测叠加层中的当前参与对象/角色高亮只从已筛选集合计算，避免隐藏的行为仍影响画面高亮。

以下内容不受筛选影响：

- 总数和各类别统计；
- 视频播放、当前时间和审核历史；
- 通过/退回的对象与结果。审核仍针对完整 Submission，筛选绝不改变提交数据或裁决范围。

选择语义采用一个明确规则：**没有选中的类别按钮始终且仅表示“全部”**，“全部”按钮此时保持按下状态，不存在“零选择 = 空结果”的状态。默认进入“全部”；在“全部”状态点击任一类别会切换为仅选该类别；之后点击未选类别会加入组合，点击已选类别会将其移出；移除最后一个已选类别时自动回到“全部”；点击“全部”会清空类别集合并恢复完整展示。即使所有实际类别分别被选中，界面仍显示这些类别均被选中，而不偷偷改写成“全部”。

切换视频时筛选重置为“全部”。筛选本身不 seek、不暂停、不播放，也不更改当前时间。

### 4.3 点击行为标注项

整行行为标注改为可激活控件，而不是只让名称或时间可点。鼠标点击、触屏轻点以及键盘 `Enter`/`Space` 的结果一致：

1. 调用现有 `seekTo(start_time)`，定位到该行为标注的开始时间；
2. 保持原播放状态：播放中则从新位置继续播放，暂停中则定位后保持暂停；
3. 将该行为标注设为当前定位目标并使用已有 `.anno-row.active` 视觉样式高亮；
4. 不自动改变筛选，不展开详情，不触发编辑。

当前时间可能同时落入多条重叠行为标注。为保证点击结果确定：

- 刚点击的行为标注在播放头仍位于其区间内时优先作为当前项；
- 播放头离开该区间后清除点击优先级，再按当前显示集合的既有顺序取第一条命中项；
- 切换筛选或视频时，如果当前目标不再可见，则清除该目标。

滚动采用克制默认：点击后**不自动滚动整个页面，也不把播放器强制拉回视口**；点击项本身已经可见，保持页面位置和键盘焦点可避免审核列表跳动。播放推进也不自动滚动列表。高亮和播放器时间显示负责反馈定位结果。

### 4.4 时间轴

- 标注区间背景色取对应类别颜色，与概览色块和列表色块保持同源；不可用时使用中性灰。
- 过滤后的时间轴只接收过滤后的行为标注数组，不通过透明度“隐藏”无关区间，避免不可见元素仍参与命中或辅助技术读取。
- 不给 `.timeline-interval` 增加 click、button、tab stop 或 seek-to-start 处理。点击标注区间所在位置时，只沿用时间轴容器现有“按点击坐标 seek”行为。
- 保留当前播放头的强调色，不用类别色替代，以明确区分“当前时间”和“行为类别”。
- 重叠区间沿用当前叠放方式；本任务不新增多轨布局。

## 5. 状态与反馈

| 状态 | 行为概览与筛选 | 列表与时间轴 |
|---|---|---|
| 未选择视频 | 不展示 | 沿用“请选择要审核的视频”空态 |
| 审核数据加载中 | 不展示旧视频统计 | 清空旧视频数据，沿用加载状态 |
| 快照无行为标注 | 显示“共 0 条 · 0 类”，不显示类别筛选项 | 列表沿用“暂无行为标注”；时间轴无区间；通过仍禁用 |
| 颜色加载中 | 统计和筛选立即可用，色块暂用灰色 | 列表和时间轴暂用灰色，不阻塞审核 |
| 颜色加载失败/409 | 保留全部控件并给出弱提示 | 全部灰色回退，不升级为页面错误 |
| 类别缺失或颜色非法 | 仅该类别灰色 | 名称、数量、区间和参与对象照常显示 |
| 筛选后无结果 | 正常情况下不会出现，因为选项只来自实际快照且最后一个类别取消后自动回到“全部”；若状态竞争导致，显示“当前筛选下暂无行为标注”并提示选择“全部” | 时间轴无区间，但总统计不变 |
| 视频时长不可用 | 概览、筛选和列表仍可用 | 列表点击仍按快照时间尝试定位；时间轴沿用“暂无时长信息” |

## 6. 响应式设计

- **宽屏**：行为概览标题、总计与筛选项在同一卡片内紧凑换行；继续使用当前 300 px 审核队列和双列审核详情。
- **≤960 px**：沿用审核队列与详情纵向堆叠；筛选项单行横向滚动，不让 12 类行为形成过高的按钮墙。滚动区域两端保留少量内边距。
- **≤640 px / 粗指针**：行为筛选项和行为标注整行的最小触控高度为 44 px；长名称省略但通过 `title` 或等价可访问名称提供完整文本；时间与状态不可被挤出屏幕，可换行到下一行。
- 页面不依赖 hover 才显示关键统计或操作；深色模式继续使用现有变量，并保留色块/时间轴区间边框以增强边界。

## 7. 键盘与可访问性

- 类别筛选使用真实 `button`，以 `aria-pressed` 分别表达每个类别的多选状态；“全部”仅在类别集合为空时为按下状态；容器提供“按行为类别筛选”的可访问名称。
- 按钮可按正常 Tab 顺序到达；`Enter` 和 `Space` 激活。不要另造全局快捷键，以免和播放器 Space、左右逐帧冲突。
- 行为标注项使用真实 `button` 或等价的单一交互元素，不能在可点击 `div` 内再嵌套按钮。其可访问名称至少包含行为名称、开始时间、结束时间和参与对象摘要。
- 当前行为标注用视觉高亮及 `aria-current="true"`（或语义等价属性）共同表达，不能只改变边框颜色。
- seek 后用现有时间显示更新提供视觉反馈，并增加简短的 `aria-live="polite"` 状态，例如“已定位到 攻击，00:12.400”。不转移键盘焦点。
- 筛选状态、数量和名称均有文本；色块设置为装饰元素并对辅助技术隐藏。
- 不新增自动动画。若高亮使用过渡，遵循 `prefers-reduced-motion`；本方案不要求滚动动画。

## 8. 实现边界

最小实现可完全在前端完成：

- 复用审核队列已经内联的完整 `submission_annotations`；
- 复用现有 `listCategories(projectId)`、`seekTo`、`activeSnapshot`、`.anno-row.active`、`.swatch` 和 `Timeline` 的 `categoryById`；
- 仅增加当前视频的筛选状态、派生统计和类别颜色的非阻断加载；
- 不引入新依赖。

颜色合并建议形成“快照类别展示对象”：名称/分组来自快照，颜色/排序可来自当前类别。不要用当前 `Category` 整体替换快照，也不要继续人为构造 `color: null` 的类别数组。

## 9. 已确认决策

1. **筛选选择方式**：采用多类别组合，已选类别按并集展示；空类别集合明确表示“全部”，不表示空结果。
2. **筛选同步范围**：同步影响行为列表、时间轴和画面参与对象/角色高亮，三个区域始终表达同一筛选集合。
3. **数量统计口径**：按当前 Submission 快照中的行为标注条数计数；总数与各类别数不随筛选变化。
4. **颜色与定位**：当前锁定类别方案只按 `category_id` 补充颜色，失败或无效时灰色非阻断回退；点击行为项定位到 `start_time` 并保持原播放/暂停状态。

## 10. 明确不做

- 不增加点击时间轴标注区间跳到区间起点的专属交互。
- 不增加审核队列服务端筛选、分页、搜索或统计接口。
- 不增加按标注人/审核人筛选。
- 不改变 Submission、SubmissionAnnotation、Review 或审核裁决语义。
- 不做类别颜色快照字段、数据库迁移或历史快照回填；提交时冻结颜色另行立项。
- 不增加持续时长统计、图表、百分比或导出功能。
- 不新增时间轴多轨布局、区间拖拽、区间编辑或列表编辑。
- 不新增依赖，不改动项目全局视觉系统。

## 11. 验收标准 / 验证建议

### 11.1 功能验收

1. 选择含多个类别的待审核视频后，概览总数等于 `submission_annotations.length`，每类计数之和等于总数。
2. 从“全部”点击某类别后，列表、时间轴与画面高亮只使用该 `category_id`；继续选择另一类别后展示两类并集；取消任一类别只移除该类，取消最后一类或点击“全部”完整恢复。总数和各类计数始终不变。
3. 点击任一行为标注项后，`video.currentTime` 定位到其 `start_time`（允许浏览器媒体 seek 的微小误差），播放/暂停状态不改变，该项高亮。
4. 对重叠行为标注逐项点击，点击项均能成为当前高亮，不被数组中更早的重叠项抢占；播放头离开区间后优先级解除。
5. 时间轴区间、列表色块和概览色块对同一 `category_id` 使用同一颜色。
6. 点击时间轴区间处仍只按点击坐标 seek，不出现跳到区间起点的新行为。
7. 切换视频后筛选恢复“全部”，旧视频计数、高亮和颜色错误提示不残留。

### 11.2 回退与边界验收

1. 模拟类别接口 409、网络错误、缺失类别、`color: null` 和非法颜色；审核快照仍完整可见、筛选可用、通过/退回不受影响，异常类别灰色显示。
2. 验证无行为标注、无视频时长、极短区间、长类别名称、12 类及更多类别、重叠区间。
3. 验证筛选不会改变送往审核接口的数据，也不会把“当前显示数”用于通过按钮门禁。

### 11.3 可用性与可访问性验收

1. 仅用键盘完成类别筛选、行为标注定位、播放/暂停与逐帧；Space 在筛选按钮或行为项聚焦时只激活该控件，不误触播放器全局快捷键。
2. 屏幕阅读器可读出筛选名称/数量、选中状态、行为项完整时间信息和定位结果。
3. 在 1440 px、960 px、640 px 和窄手机宽度检查无横向页面溢出；触控目标至少 44 px。
4. 在浅色、深色、高对比度与 `prefers-reduced-motion` 环境检查高亮和类别区分不只依赖颜色。
