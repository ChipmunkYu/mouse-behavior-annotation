## 1. 背景与目标

本次改动基于既有“我的任务 / 待领取 / 全部”三视图、负责人筛选和 checkbox 批量选择，收紧待领取与领取语义，并补齐 owner/admin 桌面框选及视频列表响应式布局。后续已将同一框选能力按角色×视图扩展给 member 的“待领取”批量自领，增量契约见[批量领取与入口精简改动说明](视频列表批量领取与入口精简改动说明.md)。

本改动已完成三件事：

1. 把“待领取”固定为**未分配且为草稿**的视频，并由后端列表与领取 CAS 共同保证这一不变量。
2. 在 `VideosPage` 中为 owner/admin 三视图及 member“待领取”提供桌面鼠标拖动框选，同时保留并统一单击、组合键、checkbox 和全选行为。
3. 收敛视频工具栏、批量栏、卡片文本和控件尺寸，使宽屏、中屏、窄屏及高倍缩放下均保持清楚、可操作。

本文独立记录本次已实现改动、固定规则和验收边界。当前分工模型、角色权限和媒体处理契约仍以现行设计为准；本文状态不表示已经提交、合并 `main` 或部署。

## 2. 非目标

- 不把框选扩展到审核工作台、视频片段库或标注页；本文中的“所有视频选择界面”只指 `VideosPage` 的“我的任务 / 待领取 / 全部”三个视图。
- 不改变“任一 active 项目成员均可领取”的既有权限，也不把负责人变成编辑权限边界。
- member 与 `member + can_review` 仅在“待领取”启用选择和批量自领，不在“我的任务”或“全部”启用，也不获得批量改派、负责人选择或清空权限。
- 不新增任务表、分工历史、分页协议或跨页选择，不改变上传、转码、播放、检测结果、标注、审核、视频片段及导出等媒体契约。
- 不重写整篇现行分工设计；本次只同步发生变化的领取不变量、统计字段和界面规则。

## 4. 固定规则一：待领取与领取不变量

### 4.1 列表契约

- `GET /api/projects/{project_id}/videos?view=unassigned` 必须由后端隐含增加以下两个条件：
  - `Video.assignee_membership_id IS NULL`；
  - `Video.workflow_status = "draft"`。
- 该条件不能只靠前端默认筛选实现。即使调用方绕过页面直接请求接口，也只能得到未分配草稿。
- 如果请求同时传入 `workflow_status`，它仍与固定条件按 AND 组合：`draft` 返回正常结果，其他状态返回空列表，不得放宽 `view=unassigned` 的固定条件。
- 前端进入“待领取”时不展示会改变这一固定条件的工作流状态筛选；搜索仍可用，但只在后端返回的未分配草稿中按文件名过滤。
- “我的任务”和“全部”继续允许四种 `workflow_status` 筛选，不受本规则影响。

### 4.2 领取 CAS 与冲突

- `POST /api/projects/{project_id}/videos/{video_id}/claim` 的单条条件更新必须同时要求：项目和视频匹配、`assignee_membership_id IS NULL`、`workflow_status = "draft"`。
- 领取检查必须留在同一个条件更新中，不得先读状态再无条件写负责人。
- 视频不存在或不属于项目仍返回 404；视频已被领取，或在用户看到列表后已变成 `submitted/approved/rejected`，均返回 409。
- 409 文案应能覆盖“已被领取或已不再是草稿”的情况；前端收到冲突后刷新列表并给出可理解提示，不把状态竞争误报成成功。
- 必须测试并发状态变化：列表读取后、领取写入前，另一个事务把草稿推进为其他状态时，领取不能写入负责人。

### 4.3 两种统计口径

- 管理统计中的 `unassigned` 保持“全部未分配”语义，统计四种工作流状态内所有未分配视频，不改名、不缩窄。
- 统计响应新增并明确 `claimable`（界面文案“可领取数”）：只统计 `assignee_membership_id IS NULL AND workflow_status = "draft"`。
- “待领取”页签数量使用 `claimable`；管理统计和“未分配”汇总继续使用 `unassigned`。任何界面不得把两者都写成“待领取”或共用同一数字。
- `AssignmentStatsOut`、前端 `AssignmentStats` 类型和相关 API 测试必须同步增加该字段。

## 5. 固定规则二：视频列表框选交互

### 5.1 范围、权限与可选对象

- 生效页面固定为 `VideosPage` 的“我的任务 / 待领取 / 全部”三个视图。
- 设备满足桌面精细指针条件时，owner/admin 在三个视图启用框选；member 与 `member + can_review` 仅在“待领取”启用，`can_review` 不扩大分工管理权限。
- owner/admin 在“我的任务/全部”只选择可批量改派的 `draft/rejected`，在“待领取”选择可分配的未分配 `draft`；两种 member 在“待领取”只选择未分配 `draft` 并批量自领。其他卡片不响应单击选择、框选或全选。
- 选择集只保存当前页面当前可见、当前可改派的视频 ID，不做跨筛选、跨视图或跨页持久化。

### 5.2 指针状态机

1. 在视频网格允许区域按下主按钮时进入“待判定”状态，保存起点、pointer ID、当前选择快照和网格边界，并调用 pointer capture。
2. 移动距离未超过 **4–6 px** 时仍按点击处理；当前实现固定使用 5 px 阈值，不随卡片尺寸变化。
3. 超过阈值后进入框选：显示选择矩形，并按卡片**中心点是否落入矩形**判断命中，避免只擦过边缘就误选。
4. 无组合键拖动以当前矩形命中项替换原选择；`Shift` 拖动把命中项追加到按下前快照；`Ctrl`（Windows/Linux）或 `Cmd`（macOS）拖动按快照逐项切换命中项。
5. 靠近网格可滚动视口上下边缘时自动滚动；滚动期间持续按页面坐标更新矩形和命中项，松开主按钮后提交当前选择并释放 pointer capture。
6. 手势期间按 `Esc` 必须取消本次手势、恢复按下前选择、停止自动滚动、移除矩形并释放 pointer capture。
7. `pointercancel`、窗口失焦、组件卸载也必须执行安全清理；不得留下矩形、滚动循环或全局 `user-select: none`。

### 5.3 点击、checkbox 与全选

- 可选卡片上的普通单击：只选中该卡片并清除其他选择；单击已唯一选中的卡片保持选中，避免进入视频前误清空。
- `Shift+单击`：在当前选择上追加该卡片；`Ctrl/Cmd+单击`：切换该卡片。这里不引入依赖排序锚点的区间选择。
- 卡片 checkbox 始终逐项切换，不受 Shift/Ctrl/Cmd 语义影响；操作 checkbox 不启动框选。
- 全选只覆盖当前搜索和筛选结果中的可选视频；短标签按场景固定为“全选可改派视频”“全选可分配视频”或“全选待领取视频”，完整范围写入 `aria-label`。全选时为 checked，部分命中时用 `indeterminate`，无可选项时禁用。
- 视图、工作流筛选、负责人筛选或搜索变化后，立即从选择集中移除所有不再可见或不再符合当前分配、改派、自领资格的视频；视图切换可直接清空。批量栏计数必须始终等于实际可提交 ID 数。
- 卡片空白区域只用于当前场景的选择，不承担导航；视频卡片仅“我的任务”显示“进入标注”，“待领取”只显示“领取任务”，“全部”不显示分工或标注主操作，仅显示独立“预览视频”。预览按钮是选择排除区域，未分工视频同样可预览。

### 5.4 手势排除与设备降级

- 从按钮、链接、input/select/textarea、label、checkbox、其他表单控件、可复制文本区域或显式交互控件开始的 pointer 手势不启动卡片点击选择或框选。
- 文件名、用户名及需要复制的元数据文本保持可选择；仅在框选已经越过阈值后临时启用 `user-select: none`，结束或取消时立即恢复。
- 粗指针设备或视口宽度 `≤760px` 关闭拖动框选和卡片单击选择，保留 checkbox 与全选，防止与触屏滚动冲突。
- 设备条件变化时若正在框选，应取消手势并恢复快照；不能只用 CSS 隐藏矩形而保留监听。

### 5.5 视觉与无障碍反馈

- 框选矩形使用主题变量提供清晰边框和半透明填充，在深浅色下均与卡片内容区分；矩形不拦截 pointer 事件。
- 已选卡片只保留左上原生 checkbox 勾、现有轮廓和浅背景，删除右上伪元素生成的第二个勾；不可选卡片不能呈现可选择光标或悬停暗示。
- 网格提供可见的 `:focus-visible` 焦点；框选结束后焦点回到网格选择区域，checkbox 仍可独立键盘聚焦。
- 增加 `aria-live="polite"` 状态文本，宣布“已选择 N 个视频”“已取消框选”及筛选后选择被清理的结果；批量栏现有区域标签继续保留。
- 触屏保留的 checkbox/全选点击目标至少 44 px；不能只放大视觉符号而不扩大 label 的可点击区域。

## 6. 固定规则三：布局与响应式

### 6.1 文本折行规则

- 短按钮、状态徽标、页签数量、批量栏中的“已选 N 个”“改派给”“应用”“取消选择”等短标签统一 `white-space: nowrap`。
- 视频文件名保持两行截断，不能为了整齐改成单行；长文件名必须在两行边界内断开且不能撑宽卡片。
- 长用户名保持单行省略，并为其 flex 子项设置 `min-width: 0`；完整用户名通过现有 title 或等价可访问方式查看。
- 空状态说明、错误、成功提示和解释性文案允许自然换行，不套用全局 nowrap。

### 6.2 工具栏收缩关系

- 对视频工具栏按上下文设置 `flex-basis`、合理 `min-width` 和子项 `min-width: 0`：搜索框优先获得剩余空间，筛选 select 保持可读下限，刷新等短按钮按内容宽度。
- 不给所有 input、select、button 设置同一个固定宽度；也不使用会让长用户名撑破容器的内容宽度。
- 批量栏允许在中屏换成两行：选择计数和短标签不拆字，负责人 select 可增长、可收缩、内部文本省略，操作按钮保持完整文字。

### 6.3 尺寸与断点结果

- 桌面控件可操作高度不低于 32 px；触屏控件不低于 40 px，checkbox、主要操作按钮等关键目标达到 44 px。
- 宽屏（以 1366 px 验收）工具栏与批量栏优先单行；中屏（以 760 px 上方至 1366 px 下方及 200% 缩放验收）允许稳定分成两行；窄屏（`≤760px`，重点检查 640/320 px）按逻辑顺序堆叠。
- 页签在窄屏继续横向滚动而不是压缩文字；任何短文字不得在控件内部折行，页面不得出现由工具栏、批量栏或长文本造成的水平溢出。

## 10. 人工验收矩阵

| 维度 | 检查组合 | 通过标准 |
|---|---|---|
| 角色 | owner、admin、member、`member+can_review` | 前两者三视图可管理选择；两种 member 仅待领取可框选和批量自领。 |
| 视图 | 我的任务、待领取、全部 | 三视图选择状态独立清理；待领取只有未分配草稿并显示“可领取数”。 |
| 状态 | `draft/submitted/approved/rejected` | 仅 `draft/rejected` 有可选反馈；`submitted/approved` 不可误选。 |
| 并发 | 打开待领取后，由另一会话领取或改变状态 | 当前会话领取得到明确 409 提示并刷新，不能显示假成功。 |
| 鼠标 | 普通/Shift/Ctrl/Cmd 单击与拖动、边缘自动滚动、Esc | 集合语义符合第 5 节；拖动不卡住文本选择；取消完整恢复。 |
| 触屏 | 真机或 coarse pointer 模拟 | 页面可正常纵向滚动，无框选；checkbox 及关键目标点击区域至少 44 px。 |
| 宽度 | 320、640、760、1366 px | 320/640 堆叠，760 边界不冲突，1366 优先单行；无水平溢出和短标签折行。 |
| 缩放 | 浏览器 200% | 逻辑顺序不乱，工具栏/批量栏可换行，焦点与操作不被遮挡。 |
| 极端文本 | 超长中英文文件名、超长用户名 | 文件名两行截断；用户名单行省略；提示文案可换行；卡片和控件不被撑宽。 |
| 主题 | 浅色、深色 | 框选矩形、选中标记、focus-visible、禁用态均清楚，不能只靠颜色传达选中。 |
| 无障碍 | Tab、Space、读屏状态区域 | checkbox 可键盘操作；焦点可见；选择数量和取消/清理结果由 aria-live 宣布。 |
