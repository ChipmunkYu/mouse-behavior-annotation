# 视频同步硬删除需求规格

> 状态：需求规格，删除功能关键决策已确认，尚未实现
> 日期：2026-08-22
> 基线：`origin/main@59965e3`
> 对应工作项：WI-20260805-22
> 约束：不新增数据库字段；本文件只定义视频删除，不定义本轮标注流程重梳与时间/帧边界修复

## 1. 背景与问题

系统目前没有删除视频 API 或视频库删除入口。直接删除 `Video` 也不能满足需求：

- `Submission.video_id`、`DetectionSnapshot.detection_import_id` 等不可变权威链使用 `RESTRICT`；
- `submission_annotations`、快照、快照状态和已被快照引用的原始检测受 SQLite trigger 保护，普通级联删除会被拒绝；
- 原视频、检测导入文件、片段、缩略图和导出 ZIP 分散在多个受控目录；
- 媒体任务和项目导出任务可处于 `queued/running`，其中一次项目导出可能同时包含目标视频与其他视频；
- `VideoImportBatch.created_video_id` 只会在视频删除后 `SET NULL`，若不主动处理会留下批次记录和重复文件引用；
- 数据库与文件系统之间没有共同事务，进程崩溃时可能出现“数据库已删、文件残留”或相反状态。

因此，本功能必须是一个受权限、状态、并发门禁和可恢复清理协议保护的业务操作，不能等同于 `db.delete(video)`。

## 2. 目标

1. 允许经确认的项目管理角色对单个视频执行**同步硬删除**。
2. 删除成功响应返回前，目标视频应从业务查询中消失，所有仅属于该视频的数据库记录与实体文件均完成清理。
3. 安全处理引用目标视频的排队中或运行中媒体/导出任务，禁止删除后重新发布片段或 ZIP。
4. 不新增软删除标记、删除状态、墓碑或其他数据库字段。
5. 删除过程具有明确的失败结果、残留检测与恢复办法。
6. 不影响同项目其他视频、其他项目、类别方案、成员或无关任务。

## 3. 非目标

- 不提供回收站、撤销删除、延迟删除或批量删除。
- 不保留被删视频的标注、审核、提交快照或导出历史。
- 不删除项目、用户、类别方案或共享配置。
- 不处理项目外文件、越界路径或无法证明由系统持有的文件。
- 不在本功能中修改标注流程、时间输入方式或 inclusive end frame 转换；这些由后续独立规格补充。
- 不承诺数据库与文件系统具备真正的分布式原子事务；按第 11 节已确认的隔离清单恢复策略控制该边界。

## 4. 术语

| 术语 | 定义 |
|---|---|
| 同步硬删除 | 客户端发起删除后保持请求，直到删除成功或得到明确失败；成功后不保留业务可恢复记录。 |
| 目标视频 | URL 中 `project_id + video_id` 唯一定位且仍属于该项目的视频。 |
| 关联任务 | payload 或冻结权威引用直接或间接包含目标视频的媒体任务或项目导出任务。 |
| 独占删除门禁 | 删除期间阻止同一视频继续标注、提交、审核、检测替换、媒体生成或其他写入的并发控制。 |
| 实体文件 | 原视频、导入批次/检测文件、片段、缩略图、导出 ZIP 及本次任务临时产物。 |

## 5. 用户故事

### US-1 删除视频

有权限的用户在视频库看到删除入口，查看不可逆影响摘要，明确确认后删除视频。

### US-2 防止误删

无权限用户、非 active 成员、跨项目请求或不允许状态下的请求必须被拒绝，且不得改变数据库、任务或文件。

### US-3 处理运行任务

若目标视频正在生成片段或参与项目导出，系统按已确认策略取消并等待相关 worker 停止发布，然后再完成删除。

### US-4 失败可诊断

任一步骤失败时，调用者得到稳定错误；运维者可判断删除是否未发生、已发生但仍有待清理残留，或可安全重试。

## 6. 权限与可删除状态

已确认：

| 决策 | 结论 |
|---|---|
| 删除角色 | active `owner/admin` |
| 允许状态 | 仅 `draft/rejected`；`submitted/approved` 必须拒绝，不能以确认或 `force` 绕过 |
| 高风险状态确认 | 不适用，因为 `submitted/approved` 不允许删除 |

同时确认：owner/admin 不受负责人限制；`draft/rejected` 使用展示完整影响范围的普通危险确认，不要求输入文件名。

无论采用何种选项，后端都必须重新验证 active membership、角色、项目归属和最新工作流状态；前端隐藏按钮不能替代授权。

## 7. 入口与 API 契约

### 7.1 后端端点

```http
DELETE /api/projects/{project_id}/videos/{video_id}
```

建议成功响应：`204 No Content`。删除前检查失败不产生副作用。

建议错误语义：

| 状态码 | 场景 |
|---:|---|
| 403 | 非 active 成员或角色无权删除 |
| 404 | 项目内不存在该视频；重复删除也返回 404，不泄露跨项目资源 |
| 409 | 视频不是 `draft/rejected`、同视频有竞争写、任务无法在等待期限内停止，或删除已由另一请求占用 |
| 500 | 删除过程发生内部错误；响应必须区分“未删除”与“数据库已删但残留待恢复” |

端点不需要确认文件名请求体或查询参数；不得使用 `force=true` 绕过权限、状态或路径安全检查。

### 7.2 前端入口

- 仅在“全部”视频视图的单视频卡片提供删除入口；首版不复用批量选择，避免误触批量硬删除。
- 入口仅向有权限角色显示，但所有安全判断以后端为准。
- 确认框展示：文件名、工作流状态、负责人、标注数量、提交/审核历史、片段数量，以及“源视频、检测数据、标注、审核、片段和相关导出将永久删除”。
- 删除期间禁用该卡片重复操作；成功后刷新视频列表和分配统计并清除本地选择。
- 失败时保留卡片并展示可执行建议，不得先从 UI 乐观移除。

## 8. 删除范围

### 8.1 必须删除的数据库记录

以删除前冻结的目标 ID 集合为准，显式盘点并删除：

1. `Video`。
2. 当前 `Annotation`、legacy `Review`、legacy `Clip`。
3. `Submission`、`SubmissionAnnotation`、绑定 Submission 的 `Review` 与 `Clip`。
4. 仅被目标视频 Submission 使用的 `DetectionSnapshot`、`DetectionSnapshotState`。
5. `DetectionImport` 及其 `RawDetection`、`DetectionStateOverride`、`DraftIdentityEdit`、`DraftDetectionChange`。
6. 迁移兼容表：`CorrectedTrack`、`CorrectedDetectionAssignment`、`IdentityEdit`、`DetectionSuppression`、`SuppressionDetection`。
7. `VideoImportBatch.created_video_id` 指向目标视频的批次记录；不只将外键置空。
8. 所有关联媒体任务和关联项目导出任务的 `BackgroundJob` 记录。

删除顺序必须由专用服务控制，不能依赖当前 ORM cascade 恰好成功。实现可以调整外键/trigger 或提供受严格约束的权威删除通道，但不得削弱正常业务路径的不可变保护；删除结束后所有 authority triggers 必须仍存在且有效。

若同一 `DetectionSnapshot` 意外被其他视频引用，删除必须拒绝并报告完整性冲突，不得级联破坏其他视频。

### 8.2 必须删除的实体文件

- `videos_dir` 中目标 `Video.storage_path` 对应的原视频；
- `detection_imports_dir` 中目标导入的 `tracks_path`、`metadata_path`；
- 与目标视频已完成/失败批次对应的 `import_batches_dir` 文件，以及批次引用的原视频/检测文件；
- `clips_dir` 与 `thumbnails_dir` 中所有目标 Clip 文件；
- 任何包含目标视频冻结 Submission 的项目导出 ZIP；
- 本次取消媒体/导出任务留下的 staging、临时 ZIP 或任务临时源文件。

所有路径必须先通过既有受控根目录解析规则；禁止跟随越界路径、目录目标或不可信 symlink。相同实体路径须去重后只删除一次。路径为空或文件本来不存在可记为“已清理”，越界路径必须视为安全错误而不是直接删除。

### 8.3 不删除的内容

- 项目、成员、类别方案和类别审计；
- 其他视频及其数据库记录和实体文件；
- 不含目标视频的媒体/导出任务和 ZIP；
- 全局 cleanup 任务与清理问题日志。

## 9. 关联任务处理

### 9.1 任务识别

删除开始时，在同一冻结视图内解析：

- legacy media payload 的 `video_id`；
- Submission media payload 的 `submission_id/submission_annotation_ids`；
- export payload 的 `submission_ids/submission_annotation_ids/refs`；
- 已成功 export 的冻结 payload，用于判断其 ZIP 是否包含目标视频。

不能只按 `project_id` 删除任务；项目导出可能只包含其他视频。

### 9.2 queued 任务

- 通过条件更新将任务从 `queued` 改为已有终态 `cancelled`，阻止 worker claim；
- 清理该任务已存在的 staging/结果文件；
- 在最终数据库清理阶段删除任务行。

### 9.3 running 任务

- 先把关联任务标记为 `cancelled`，并让 worker 在每个昂贵阶段前、原子发布前和完成写回前检查 claim/status；
- 运行中的 ffmpeg/ZIP 允许当前命令结束但必须禁止发布，删除请求按第 9.4 节最多等待 30 秒；
- 删除端点必须等到 worker 已不再持有目标文件、不会再创建或发布目标产物，才能进入最终删除；
- 项目导出只要冻结集合包含目标视频，整项导出取消并清理；不得静默生成缺少目标视频的缩水 ZIP；用户可在删除后重新发起导出。

当前 worker 仅在部分最终发布处复核 job 状态，Submission media 路径不会完整协作取消；实现前必须补齐，不能靠删除数据库行让线程自行报错。

### 9.4 等待策略（已确认）

采用有限等待：先取消关联任务的发布权并等待 worker 释放文件，最长 30 秒。30 秒后仍未停止则返回 409，本次不移动文件、不删除业务数据，用户稍后重试。不主动终止 ffmpeg/ZIP 子进程，也不无限保持 HTTP 请求。

## 10. 并发与一致性

1. 删除必须与同视频标注 CRUD、检测替换、track 修正、提交、撤回、审核、媒体生成和分配写操作竞争同一独占门禁。
2. 获取门禁后重新读取权限、项目归属、工作流状态、Submission、任务和路径集合；门禁外预检只能用于快速失败。
3. 第二个删除请求不得重复执行；首个未完成时返回 409，首个成功后返回 404。
4. worker 任何最终发布都必须验证其 job 仍为 `running` 且冻结 payload 未变；`cancelled` 后不得改回 `succeeded/failed` 或写回文件路径。
5. 删除成功后，流媒体、标注、审核、片段和任务接口均不得再返回目标视频数据。
6. 不允许以长期持有 SQLite 写锁的方式等待 ffmpeg；任务停止等待与最终短数据库事务必须分离。

## 11. 失败恢复策略（已确认）

数据库与文件系统无法共同原子提交。采用**受控隔离目录 + 删除清单**：

1. 预检并冻结数据库 ID、文件 identity 与规范化路径，写入同一数据盘的删除清单；
2. 取消并等待关联任务；
3. 将可控文件原子移动到删除隔离目录；任一移动失败则恢复已移动文件，数据库不变；
4. 在短 `BEGIN IMMEDIATE` 内通过专用删除通道删除全部关联记录，执行外键检查与残留计数后提交；
5. 提交后物理删除隔离目录；全部成功后删除清单并返回 204；
6. 若数据库提交失败，按清单恢复文件；若数据库已提交而最终 unlink 失败，由启动恢复/运维命令继续清除隔离目录，不得把数据库记录伪造回来。

删除清单是文件系统恢复工件，不是数据库字段；不得包含凭据，路径只记录受控相对 key 与文件 identity。

采用受控隔离目录 + 删除清单与**严格同步**成功语义：隔离目录物理清空后才返回 204。数据库已提交但最终 unlink 失败时返回 500，错误明确说明业务数据已删除、实体残留将由恢复器继续清理；客户端不得把该结果解释为“视频仍存在”并反复创建同 ID 请求。启动恢复或运维命令必须按清单继续清理，不能伪造恢复已删除的数据库记录。

## 12. 可观测性与审计边界

- 因为是硬删除且不新增数据库字段，成功后不保留目标视频业务审计行。
- 应在应用日志记录操作者用户 ID、项目 ID、视频 ID、开始/结束时间、取消任务 ID、各类删除计数、最终阶段和错误摘要；禁止记录 token、绝对敏感路径或文件内容。
- 文件删除失败继续复用 `cleanup-issues.log` 的受控 JSONL 思路，或使用独立删除恢复清单；具体 owner 待实现设计确定。
- API 错误不得暴露服务器绝对路径、SQL 或命令行详情。

## 13. 验收标准与证据路径

### 13.1 权限与状态矩阵

- active owner/admin（以最终决策为准）在每个允许状态可删除；其他角色、inactive 成员和跨项目请求均失败且零副作用。
- 状态在确认框打开后变化时，后端按最新状态重新判断。

### 13.2 数据库完整性

- 构造同时含 Annotation、多个导入修订、draft edit、Submission 全生命周期、Review、Clip、批次和任务的视频；删除后逐表断言无目标关联行。
- 运行 `PRAGMA foreign_key_check` 无结果；正常不可变 trigger 在删除后仍能拒绝违规 UPDATE/DELETE。
- 同项目其他视频与共享类别、成员、项目审计的行数和关键摘要不变。

### 13.3 文件完整性

- 对各受控目录建立明确文件清单；删除后目标文件、关联 ZIP、staging 和临时文件均不存在，其他视频文件 SHA-256 不变。
- 文件缺失、重复路径、越界路径、symlink、目录目标、权限不足和 unlink 失败均有专项测试。

### 13.4 任务竞争

- queued media、running media、queued export、running export、已成功 export 五类场景均覆盖。
- 通过可控 worker barrier 在“claim 后”“ffmpeg 后”“ZIP 发布前”触发删除，证明删除成功后任务不能发布、复活 Clip 或改写已删行。
- 多视频导出含目标视频时整项取消；不含目标视频的并行任务保持不变。

### 13.5 恢复故障注入

- 在文件隔离前后、数据库提交前后、最终 unlink 前后注入故障，验证恢复结果与所选成功语义一致。
- 重启恢复可从删除清单确定性完成或回滚，不依赖人工猜测。
- 同一删除请求在可重试失败后再次执行，不产生越界删除或重复任务发布。

### 13.6 前端流程

- 权限可见性、分状态确认文案、普通危险确认、loading、失败保留、成功刷新与键盘焦点均通过组件测试和人工浏览器验收。
- 删除成功后从视频库、分配统计、审核队列和片段库同步消失。

## 14. 实现前门禁

删除功能产品决策已全部确认：

1. active `owner/admin` 可删除，不受视频负责人限制。
2. 仅允许 `draft/rejected`；`submitted/approved` 必须拒绝。
3. 取消关联任务发布权后最多等待 30 秒；超时返回 409 且本次不删除，不主动终止子进程。
4. 使用受控隔离目录 + 删除清单；只有数据库记录与实体文件都清理完成才返回 204。
5. 使用普通危险确认，不要求输入文件名。

标注流程目标与结束时间/inclusive end frame 的规范将在下一份规格中单独确认，不与删除策略隐式绑定。
