# 低码率展示代理视频实现计划

> **状态：P1—P4 代码已在当前分支本地完成，尚未提交、推送或部署。** 本文记录当前候选与部署门禁；生产实时事实只查仓库外“网站服务器文件清单”。

## 1. 已实现契约

- `0016_display_proxy.py`、展示代理字段、持久任务 ownership、单 owner worker、CAS、恢复、原子发布、磁盘保护和硬删除闭环已实现。
- 新 file-backed Video 仅在 `DISPLAY_PROXIES_ENABLED=true` 时计算原片 SHA-256，并在同一事务创建代理任务；commit 后只负责唤醒 worker。multipart 上传和三文件完成入口遵循同一规则，metadata-only Video 明确排除。
- Preview、Clips、Review、Annotate 四入口共用同一媒体能力：完整认证 GET → `response.blob()` → `URL.createObjectURL()`；切换或卸载会 abort 旧请求、屏蔽晚到响应并回收 object URL。
- 开关开启时，ready 才可展示；pending/processing 返回 `409 + DISPLAY_PROXY_PENDING`，failed、缺失或不一致返回 `409 + DISPLAY_PROXY_FAILED`，不静默读取原片。
- `Video.storage_path` 始终指向原片。片段生成、Submission 冻结、缺失片段补生成和项目导出始终读取原片，展示代理不得成为业务权威。
- 候选 profile 为 1280×720、H.264/libx264、CRF 28、veryfast、yuv420p、固定 30 帧 GOP、SAR 1:1、无音频和 faststart；发布前校验 profile、时间轴、帧数、旋转与 source SHA-256。

## 2. 最终范围与唯一开关

最终方案明确：

1. **不支持历史 backfill。** 不提供 hash/代理回填 service、CLI 或启动扫描。
2. **没有独立 fallback 配置。** 不提供 `DISPLAY_PROXY_ALLOW_SOURCE_FALLBACK` 或按页面降级。
3. **只有 `DISPLAY_PROXIES_ENABLED`：**
   - `false`：四入口播放原片，新 file-backed Video 不 hash、不入队；
   - `true`：新 file-backed Video hash/入队，四入口严格只读 ready 代理。
4. 开关为 `false` 期间必须禁止新视频写入，否则这些视频日后启用 strict 时没有代理。
5. 启用前必须在维护窗口清空或重置全部旧 file-backed 数据，并留存操作证据。用户已确认可以清空，但实际服务器执行前仍须再次明确确认具体对象、备份和删除命令。

代理目录固定由 `DATA_DIR` 派生为 `DATA_DIR/display_proxies/`，不提供 `PROXIES_DIR`。配置模板固定包含：

```dotenv
DISPLAY_PROXIES_ENABLED=false
DISPLAY_PROXY_TIMEOUT_SECONDS=3600
DISPLAY_PROXY_MAX_ATTEMPTS=3
DISPLAY_PROXY_SYNCHRONOUS=false
DISPLAY_PROXY_DISK_RESERVE_BYTES=1073741824
```

生产只允许单实例、单 Uvicorn worker；禁止滚动发布、禁止新旧实例并存、禁止两个 owner 共享 SQLite 和代理目录。

## 3. 只读 preflight

生产从目标 release 的 `backend/` 运行部署指南所列安全 Python wrapper，并显式传入
`--env-file /home/jinghan/.config/mouse-annotation/backend.env`。禁止 `source backend.env`、
`. backend.env` 或 `set -a`；wrapper 先核对 `ENV=production`、生产数据/数据库目标及开关仍为
`false`，但不得打印 env 内容或 secret。本地开发才可直接运行 `python scripts/display_proxy_preflight.py`。

该命令只读数据库与已有文件状态：不写库、不计算 source hash、不运行 ffprobe，也不创建代理任务。

| 退出码 | 含义 | 处理 |
|---|---|---|
| `0` | 所有受管 file-backed Video 均满足 strict ready 条件，或库为空 | 才允许继续把开关切为 true |
| `1` | 存在 pending/failed/缺失/身份不一致等未就绪数据 | 保持停写和开关 false，处理旧数据后重跑 |
| `2` | 配置、数据库连接或检查过程错误 | 停止上线并排障 |

上线 strict 前最后一次 preflight 必须返回 `0`；旧输出或其他环境的结果不能替代。

## 4. 安全部署顺序

以下仅是部署准备，不表示服务器已经执行：

1. 固定完整 commit，创建不可变 `releases/<commit>/`。
2. 安装锁定后端依赖并 `pip check`；执行前端 `npm ci`、类型/API 检查和 production build。
3. 冻结入口、所有新视频上传/三文件完成及其他新写入，等待 display、media、export、cleanup 等相关任务进入已知终态。
4. 停止唯一 systemd 服务，确认 unit inactive、Uvicorn 退出且 8000 不再监听；后续迁移/清理期间禁止后台 worker 运行。
5. 创建 SQLite 一致性备份并对备份执行 `PRAGMA integrity_check`；记录备份路径、权限和结果。
6. 显式迁移到候选 head `0016` 并核对 revision；处理旧 file-backed 数据前再次明确对象、范围、备份与不可逆影响并留证。
7. 创建由 `DATA_DIR` 派生的代理目录，核对 owner/group、`0750` 目录权限、同文件系统原子发布条件及磁盘余量。
8. 保持服务停止和停写，使用显式 `--env-file` 的安全 wrapper 运行 preflight；只有退出码 `0` 才把稳定生产 env 的 `DISPLAY_PROXIES_ENABLED` 改为 `true`。
9. 原子切换到目标 release，启动**单实例、单 Uvicorn worker**；不得滚动双实例。
10. 上传一个有代表性的真实视频，等待代理从 pending/processing 到 ready。
11. 验证 Preview、Clips、Review、Annotate 都完整下载同一代理；验证 pending/failed 409；验证片段、Submission/审核和项目导出仍来自原片。
12. 检查应用/systemd/Nginx 日志无凭据和路径泄漏，检查代理/临时文件、磁盘 reserve、CPU、内存与 I/O；证据完整后才解除维护窗口写入。

## 5. 回滚

回滚前先冻结新视频上传并等待相关任务 terminal，再停止唯一服务。紧急停机遗留 `queued`/`running` display job 时，外部入口和所有写入必须继续冻结，且不得手工改 DB。临时以同版本、`DISPLAY_PROXIES_ENABLED=true`、唯一服务、单 Uvicorn worker 启动 recovery/worker，全程不得向用户开放；逐项监测任务到已知终态，任何任务失败、无法可靠进入终态或状态未知都必须阻断并专项处理。成功收敛后再次停止服务，确认 unit inactive、Uvicorn 退出且 8000 未监听，才继续备份、迁移、preflight 和正式启动；不得启动第二实例或并行运行其他服务。

### 一级：同 release 事故读回退

将 `DISPLAY_PROXIES_ENABLED=false` 并重启同一 release，使展示临时读取原片。此举只用于事故恢复，不表示代理兼容模式；**必须持续冻结新视频写入**，否则会产生未 hash/未入队数据，阻断再次启用 strict。保留数据库 `0016` 和代理文件以便排障。

### 二级：回到旧 release

在服务停止且备份已确认的维护窗口，先处理 schema：按迁移链从 `0016` downgrade 到 `0015`，或恢复上线前一致性备份，再切换旧 release。迁移后产生的用户写入可能在 downgrade/恢复备份时丢失，执行前必须明确数据丢失窗口并再次确认。禁止只切代码让旧 release 读取未知 schema。
