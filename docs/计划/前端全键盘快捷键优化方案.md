# 前端键盘快捷键优化方案

> 状态：本轮快捷键调整已实现；聚焦回归、`npm run typecheck`与 production build 通过，仍需人工浏览器验收
> 范围：进入视频行为标注页后的核心操作
> 目标：用少量、稳定的快捷键加速高频行为标注流程，同时保留按钮和鼠标操作；不再追求所有功能都能仅靠键盘完成。
> 术语基线：[项目术语表](../../项目术语表.md)。本文是快捷键现状与下一轮计划细节的唯一 owner；[需求文档](../../需求文档.md)只保留摘要和入口。

## 1. 当前实现与本轮计划

### 1.1 当前已经实现

以下结论以当前前端实际按键处理逻辑为准：

| 按键 | 当前操作 | 生效范围 |
|---|---|---|
| `Space` | 仅播放/暂停视频 | 标注页、审核页和片段页；输入控件、帮助或确认弹窗中不触发；聚焦按钮时阻止原生 Space 激活 |
| `Tab` | 切换行为标注 / track 修正模式 | 标注页；无有效 detection import 时保持行为标注模式并提示 |
| `Shift+Tab` | 消费按键但不执行操作 | 标注页；不触发原生反向焦点遍历 |
| `T` | 进入 / 退出当前模式的 track 列表键盘导航 | 标注页；行为模式用于无序参与对象列表，角色槽位类别仍用按钮；track 修正模式用于 track 列表 |
| `↑` / `↓` | 移动当前列表导航高亮 | 仅列表导航激活时 |
| `Enter` | 选择/取消高亮 track；非危险确认弹窗中确认 | 危险确认弹窗不响应 Enter，仍须点击确认按钮 |
| `←` / `→` | 后退/前进 1 帧 | 标注页、审核页和片段页；输入控件或确认弹窗中不触发；片段页按钮/链接聚焦时不接管 |
| `Shift+←` / `Shift+→` | 后退/前进 10 帧 | 标注页；输入控件或弹窗中不触发 |
| `Shift+Comma` / `Shift+Period`（`《` / `》`） | 上一个/下一个视频 | 标注页；按物理键识别，保护编辑、弹窗、帮助和忙碌状态 |
| `S` / `D` | 设置起点 / 设置终点并创建行为标注 | 仅行为标注模式 |
| `1`–`9`、`0` | 选择前 10 个启用行为类别 | 仅行为标注模式、视频就绪且不在输入/弹窗/编辑状态 |
| `Delete` | 打开当前模式目标的危险确认框 | 参与对象导航时无操作、无提示且不穿透 |
| `Ctrl+Z` | 撤销当前页面会话中最近一次可追踪的 track 修正 | 仅 track 修正模式；刷新边界见 4.4 |
| `?` | 打开/关闭快捷键帮助 | 输入控件中不触发 |
| `Esc` | 取消确认、关闭帮助、取消编辑或退出列表导航 | 一次只关闭一个最高优先级状态 |

### 1.2 当前实现边界

- 行为模式中的 `T`导航只覆盖无序参与对象列表；角色槽位类别继续使用角色槽位和 Track 按钮，不伪造未实现的全键盘角色分配。
- 类别接口按 `sort_order`、`id`稳定排序；前端取前 10 个启用类别映射 `1`–`9`、`0`，第 11 个以后不映射。
- 模式切换会退出两种列表导航并清除键盘高亮；已选 track、行为草稿、类别、角色分配和搜索条件继续保留。
- `Ctrl+Z`只维护当前页面会话内成功返回可撤销 ID 的操作；刷新后不会伪造无法恢复的历史。
- 输入控件仍保护文本输入，但裸 `Tab` / `Shift+Tab`按已确认规则由页面消费；带 `Ctrl`、`Alt`或 `Meta`的 Tab 组合不被页面接管。

### 1.3 本轮快捷键调整结论（已实现，待人工验收）

```text
S → 数字键选择行为类别 → T → ↑/↓ + Enter 选择参与对象 → D
Tab：切换行为标注 / track 修正
Shift+Tab：消费但不执行操作
T：进入 / 退出当前模式的 track 列表键盘导航
Space：仅播放 / 暂停视频
```

- [x] 裸 `Tab`切换模式；`Shift+Tab`消费但不执行操作；离散动作忽略长按重复。
- [x] 无有效 detection import 时，按 `Tab`保持行为标注模式并给出原因。
- [x] `T`控制当前模式的列表导航，`↑` / `↓`移动高亮，`Enter`选择/取消。
- [x] 时间轴和片段区间条不再用左右箭头跳转 1 秒；三页面左右箭头业务语义统一为按帧定位。
- [x] `Space`在标注页、审核页和片段页只播放/暂停；帮助、确认弹窗和输入控件中不触发。
- [x] 非危险确认弹窗支持 `Enter`确认；危险确认弹窗吞掉 `Enter`与 `Space`，仍须点击确认。
- [x] 参与对象导航状态下 `Delete`无操作、无提示且不穿透。
- [x] 快捷键帮助、持续状态提示和按钮文案已同步。
- [ ] Windows 主流浏览器人工验收焦点、长按、三页面 Space、两种列表滚动跟随与危险确认。

## 2. 核心行为标注流程

当前实现的核心键盘流程是：

```text
S → 数字键选择行为类别 → T → ↑/↓ + Enter 选择参与对象 → D
```

具体规则：

1. `S` 设置当前帧为行为标注起点。
2. 数字键选择对应行为类别。
3. 如果该类别需要无序参与对象、存在有效检测结果导入且参与对象列表非空，按 `T`显式进入列表导航并高亮第一项。
4. `↑` / `↓` 移动高亮，`Enter`选中或取消当前高亮的 `track ID`；移动后可以继续多选。
5. `D` 设置终点并创建行为标注，仍执行类别、起点和参与对象数量校验。
6. `T`或 `Esc`退出参与对象导航状态，已经选中的参与对象保持不变。

鼠标点击类别按钮与键盘数字选择复用同一个类别选择函数，但都不再自动进入列表导航。角色槽位类别继续通过角色槽位和 Track 按钮分配参与对象。

## 3. 设计原则

1. **高频优先**：快捷键只覆盖视频定位、行为标注、参与对象选择及少量通用操作。
2. **模式清晰**：快捷键必须根据当前工作模式、焦点和导航状态产生可预测的唯一结果。
3. **输入保护**：焦点位于 `input`、`textarea`、`select` 或可编辑元素时，不触发普通页面快捷键。
4. **弹窗优先**：确认弹窗打开时暂停页面快捷键，只允许 `Esc` 取消；危险操作不提供键盘确认。
5. **危险操作不直达**：`Delete` 只打开确认框，最终确认必须点击确认按钮，不能用 `Enter`、`Space` 或再次按 `Delete` 完成。
6. **状态可见**：参与对象导航必须同时提供明显的视觉高亮和文字状态提示，高亮与已选中状态必须可区分。
7. **按键长按保护**：除明确允许连续逐帧或跳帧外，忽略 `KeyboardEvent.repeat`。
8. **提示统一**：存在对应按钮的快捷键直接写入按钮文案，统一使用英文方括号 `[]`。
9. **边界如实可见**：快捷键帮助和 track 修正面板明确说明 `Ctrl+Z`只覆盖当前页面会话。

### 4.2 行为类别选择

| 按键 | 操作 | 状态 |
|---|---|---|
| `1`–`9` | 选择快捷键顺序中的第 1–9 个行为类别 | 已实现 |

映射规则：

1. 当前类别模型没有可用于快捷键排除的显式群体行为字段；前端不按类别名称、`group`或对象数量猜测。
2. 类别接口只返回 `is_active`类别，并按 `sort_order`、`id`排序；前端按相同字段再次稳定排序后，将前 10 个启用行为类别映射到 `1`–`9`、`0`。
3. 单对象、双对象、群体或其他类别都按显示位置参与映射；参与对象数量只用于选择校验，不用于数字映射。
4. 第 11 个及以后的启用类别不提供快捷键，继续通过按钮选择。
5. 不设计 `Ctrl+数字`、分组前缀或任何两段数字键。
6. 有数字映射的类别按钮显示 `[1]`、`[2]`等提示；没有映射的按钮不显示虚假键位。
7. 类别顺序在同一配置版本中必须稳定，避免数字含义随刷新或筛选变化。

### 4.4 track 修正模式

track 修正保留按钮和原生交互，不再为列表导航、`Split`、`Merge`、筛选或搜索分配专属快捷键。

| 按键 | 操作 | 前置条件 | 状态 |
|---|---|---|---|
| `Delete` | 为当前选中的整个 track 打开忽略确认框 | 恰好选中 1 个 `track ID` | 已实现 |
| `Ctrl+Z` | 撤销最近一次 `Split`、`Merge` 或忽略整个 track | 当前页面会话已记录可靠的可撤销 ID | **已实现，限当前页面会话** |
| `T` | 进入 / 退出 track 列表导航 | 存在有效检测导入和可用 track | 已实现 |
| `↑` / `↓` / `Enter` | 移动高亮 / 切换选择 | track 列表导航已激活 | 已实现 |
| `Esc` | 关闭确认弹窗 | 确认弹窗打开 | 当前已实现 |

`Delete`不会直接忽略数据；确认框打开后必须明确操作确认按钮。`Ctrl+Z`按当前页面会话中的实际成功顺序统一撤销；服务端未返回可撤销 ID 时不入历史。刷新后既有忽略记录仍可通过记录旁的撤销按钮处理，但无法与刷新前的 `Split` / `Merge`可靠排序，因此不进入统一快捷键历史。

### 4.5 明确取消的旧键位

以下键位不再进入计划：

- `Ctrl+←` / `Ctrl+→`跳转起点、终点或视频首尾；
- 反引号切换行为标注与 track 修正模式；
- `Ctrl+B`、`Ctrl+I`、`Ctrl+K`、`Ctrl+Shift+L`控制叠加层；
- `Ctrl+数字`加第二个数字的两段类别选择；
- `M`进入参与对象导航或执行 `Merge`；
- `Ctrl+↑` / `Ctrl+↓`导航行为标注列表；
- `E`编辑行为标注；
- `Ctrl+Enter`保存编辑表单；
- 不经 `T`激活、始终占用全局 `↑` / `↓` / `Enter` / `Space`的旧列表导航；
- `S`执行 `Split`；
- `A`切换 track 范围；
- `/`聚焦 track 搜索；
- `Enter`确认危险操作。

## 5. `T`显式列表导航

选择行为类别不会自动进入导航。行为模式按 `T`时按以下顺序判断：

1. **未选择类别**：不进入导航，提示先选择行为类别。
2. **角色槽位类别**：不进入无序列表导航，提示继续使用角色槽位和 Track 按钮。
3. **类别不允许参与对象（`mouse_count_max === 0`）**：不进入导航，提示该类别无需参与对象。
4. **没有有效检测结果导入或列表为空**：不进入导航并提示具体原因。
5. **条件满足**：高亮第一项并进入导航；`↑` / `↓`移动，`Enter`选择，`T`或 `Esc`退出。

track 修正模式按 `T`时要求存在有效检测导入和可用 track；进入后复用同一组 `↑` / `↓` / `Enter` / `T` / `Esc`规则，但写入独立的 track 修正选择状态。

“有效检测结果导入”以 `detection-imports/current`实际返回的当前 active 导入为准，并同时要求参与对象 track 列表非空；不再使用 `revision`是否大于 0 作为二次有效性判断。

导航中的视觉要求：

- 高亮项必须有独立的焦点边框或背景，不得只依赖颜色轻微变化；
- “键盘高亮”和“已经选中”使用不同样式，可以同时存在；
- 高亮移动到滚动区域外时自动滚入视野；
- 列表刷新、筛选或当前帧变化后，高亮索引修正到有效项；
- 退出导航后移除键盘高亮，但保留所有已选 `track ID`；
- 页面状态区持续显示当前是否处于列表导航状态。

## 6. 焦点与按键优先级

一次按键只能触发一个动作，按以下顺序处理：

1. 确认弹窗；
2. 输入框、文本框、下拉框和可编辑元素；
3. 快捷键帮助；
4. 参与对象导航状态；
5. 当前工作模式中的业务操作；
6. 全局视频控制。

### 6.1 `Space`优先级

1. 输入控件内保留原生输入行为。
2. 快捷键帮助或确认弹窗打开时消费按键但不执行动作。
3. 其他情况下只播放/暂停视频；即使原生按钮获得焦点，也阻止 Space 激活按钮。

参与对象导航处理器使用 `↑`、`↓`、`Enter`、`T`和 `Esc`；`D`继续交给行为标注处理器创建行为标注。导航状态中的 `Delete`无操作且不穿透。

### 6.2 `Tab`与列表导航优先级

1. 确认弹窗和快捷键帮助优先；帮助中裸 `Tab` / `Shift+Tab`只被消费。
2. 标注页裸 `Tab`切换模式；`Shift+Tab`只被消费；两者均不承担原生焦点遍历。
3. 导航激活后，`T`或 `Esc`退出，`↑` / `↓`移动，`Enter`切换选择。
4. 模式切换会退出两种列表导航并移除键盘高亮，但保留已选 track 与草稿数据。

### 6.3 `Esc`优先级

1. 关闭确认弹窗或快捷键帮助。
2. 退出当前列表导航并保留已选 track。
3. 其他没有明确取消目标的场景不执行操作。

`Esc`不再承担清空搜索、取消全部 track 选择、清除行为起点等多层隐式操作。

### 6.4 方向键优先级

1. 输入控件保留原生行为（光标移动）；片段页按钮/链接聚焦时也不接管左右键；标注页时间轴获得焦点时，左右键仍走页面级帧步进。
2. 参与对象导航状态中，`↑` / `↓`移动高亮。
3. 其他情况下，`←` / `→`逐帧，`Shift+←` / `Shift+→`跳转 10 帧。

（本轮已移除时间轴与片段区间条用左右箭头“前后 1 秒”的局部处理；除输入控件原生光标移动外，左右箭头的业务语义统一为按帧定位。）

## 7. 按钮提示规范

1. 快捷键存在对应按钮时，直接追加到按钮文案末尾，并统一使用英文方括号 `[]`。
2. 当前目标文案包括：
   - `播放/暂停 [Space]`；
   - `后退 1 帧 [←]`、`前进 1 帧 [→]`；
   - `设起点 [S]`、`设终点 [D]`；
   - 映射了数字的类别按钮显示 `[1]`至`[0]`；
   - 列表导航状态提供`退出 [T / Esc]`按钮；
   - 当前选中行为标注的删除按钮及忽略整个 track 按钮显示 `[Delete]`；
   - 当前页面会话统一撤销按钮显示 `[Ctrl+Z]`，并在旁边说明刷新边界。
3. 第 11 个及以后的类别不显示数字提示。
4. 禁用按钮仍保留已经真实实现的快捷键提示。
5. 一个按钮支持多个真实快捷键时，在同一组方括号内用 `/`分隔。
6. 不得只在 tooltip 或帮助面板中提供按钮快捷键提示。
7. 没有处理逻辑的按钮不得显示快捷键提示。

## 8. 冲突与风险处理

| 风险 | 处理规则 |
|---|---|
| 数字键与数字输入冲突 | 输入控件聚焦时不选择类别 |
| 类别按钮顺序变化导致键位变化 | 只按固定、稳定的界面顺序映射；配置变化应视为新的类别配置版本 |
| 缺少显式群体行为快捷键字段 | 不猜测类别语义，严格映射显示顺序中的前 10 个启用类别 |
| `Space`原生激活聚焦按钮 | 标注、审核和片段页统一 `preventDefault`，只执行播放/暂停；帮助和弹窗中无动作 |
| `Tab`与原生焦点遍历冲突 | 裸 `Tab`切模式，`Shift+Tab`消费无动作；带 Ctrl/Alt/Meta 的 Tab 不接管 |
| `↑/↓`与页面滚动或局部控件冲突 | 只有 `T`激活列表导航后消费；输入控件仍优先 |
| `Shift+←/→`与文本选择冲突 | 输入控件聚焦时不触发视频跳转 |
| `Shift+←/→`被普通逐帧逻辑提前消费 | 先判断带 `Shift`的组合键，再处理裸 `←/→` |
| 中英文输入法产生不同标点字符 | 视频切换只判断 `shiftKey`与物理 `code === "Comma" / "Period"`，不依赖 `key`字符 |
| 切换视频时丢失临时状态 | 有未完成起点或正在编辑行为标注时先确认；保存、提交审核或 track 操作期间禁止切换 |
| `Delete`与文本删除冲突 | 输入控件聚焦时保留原生删除；页面操作只打开确认框 |
| `Ctrl+Z`与文本撤销冲突 | 输入控件聚焦时保留原生撤销；仅 track 修正模式消费页面快捷键 |
| `?`需要部分键盘使用 `Shift`输入 | 按实际字符 `?`判断，并提供可点击帮助入口 |
| `D`在对象未选完时误提交 | 创建前继续执行参与对象数量校验并给出原因 |
| 危险操作误确认 | 非危险弹窗允许 `Enter`；危险弹窗吞掉 `Enter`与 `Space`，必须点击确认按钮 |

## 9. 边界条件

- 视频未加载完成时，播放、定位和创建行为标注相关键位不执行。
- 相邻视频使用项目完整视频列表，固定按 `created_at DESC, id DESC`排序，不按 `workflow_status`过滤；首尾禁用对应方向，当前视频不在列表时两个方向都禁用。
- 鼠标按钮和`《` / `》`快捷键复用同一导航函数；切换路由不保留旧`?t=`，并清理旧视频的播放、标注、参与对象、编辑和 track 临时状态。
- 保存行为标注、提交审核或执行 track 操作期间禁止视频切换；存在未完成起点或正在编辑行为标注时，确认取消后保持当前视频和临时状态。
- 数字对应类别不存在或未映射时，不执行类别选择并给出简短提示。
- 数字类别选择成功与进入参与对象导航是两个结果：即使没有检测导入或列表为空，类别选择仍然保留。
- 类别不要求参与对象时，不进入参与对象导航。
- 参与对象列表支持继续移动高亮并多选，不因一次 `Enter`选择而自动退出。
- `Esc`退出导航后不清空已选参与对象。
- 类别要求的参与对象数量不满足时，`D`不创建行为标注。
- `Delete`只有在当前模式存在明确、唯一且允许操作的目标时才打开确认框；参与对象导航中无操作、无提示且不穿透。
- `Split`、`Merge`和忽略整个 track 正在请求时，不允许重复提交。
- 底层仍复用 track ID 修正与检测抑制两类撤销 API；前端用当前页面会话历史按实际成功顺序统一调度 `Ctrl+Z`。
- 服务端未返回可靠操作 ID 时，该操作不进入统一历史并给出提示。
- 刷新后统一历史清空；既有忽略记录可单独撤销，但刷新前的 `Split` / `Merge`无法恢复并排序，界面必须持续显示这一边界。

## 13. 验收标准

1. 用户可以按 `S → 数字键 → T → ↑/↓ + Enter → D`完成需要无序参与对象的行为标注。
2. 不需要参与对象的类别可以按 `S → 数字键 → D`完成标注。
3. 数字键覆盖按 `sort_order`、`id`稳定排序后的前 10 个启用行为类别，不按名称、分组或对象数量排除。
4. 双对象、群体或其他类别本身不影响映射；第 11 个及以后类别继续通过按钮选择。
5. 参与对象导航状态有明确视觉高亮和持续文字提示，高亮与已选状态可区分。
6. 列表导航中的 `Enter`切换选择；`Space`始终只播放/暂停。
7. `T`或 `Esc`退出列表导航时保留已选 track。
8. `Delete`不直接执行危险操作，且危险确认必须点击按钮。
9. `Ctrl+Z`只作为当前页面会话能力出现，不声称可恢复刷新前的 `Split` / `Merge`历史。
10. 所有已实现且有对应按钮的快捷键使用英文方括号显示，如 `[S]`、`[1]`。
11. 输入控件、按钮、局部时间轴、帮助和确认弹窗不产生重复快捷键动作。
12. 已取消键位没有被意外恢复。
13. 用户可用标题区按钮或`《` / `》`在项目完整视频顺序中切换，所有工作流状态均参与，首尾边界正确。
14. 切换保护、临时状态确认、路由清理及输入/弹窗/帮助焦点边界符合第 12.5 节。
15. 裸 `Tab`切换模式，`Shift+Tab`无动作；`T`在两种模式分别控制对应 track 列表导航。
