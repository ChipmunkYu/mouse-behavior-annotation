# 播放与带宽优化计划：HTTP Range 实施

> **状态：本地候选及服务器 Linux 依赖/完整后端回归验证通过；尚待创建包含 Linux lock 的最终 release，功能尚未部署。** 本文以 `main@6d31068f24531c2d413b477e8f5b6e79b19e96b6` 为事实基线；Oracle Gate 3 follow-up 已批准本地候选验收，服务器隔离候选验证基于 `28cdba6765b119a74fc16e6e608969f4927bf3e9`，但生产能力仍须通过其余 P3/部署前门禁，任何候选证据均不得表述为已上线。

## 1. 目标、边界与已确认决策

本轮目标是让浏览器原生 `<video>` 直接使用受控媒体 URL，并由经过锁定和验证的 Starlette `FileResponse` 处理 HTTP byte-range 请求，取消前端在播放前强制整包缓冲视频的做法。

以下决策均为**已确认**：

1. 本轮只实现 HTTP Range；不实现低码率副本、HLS、CDN、缓存或转码。
2. 覆盖四个播放入口：视频库 `VideoPreviewDialog`、标注页 `AnnotatePage`、审核页 `ReviewPage`、片段页 `ClipsPage`。
3. 每视频票据 TTL 的**配置上限**固定为 **2 小时（7200 秒）**，实际有效期受当前 Bearer 剩余寿命截断，`exp = min(iat + 7200, bearer_exp)`；Bearer 到期后，已签票据不得继续访问。
4. 正式浏览器门禁为 Edge/Chrome 和 Firefox；Safari 不属于本轮门禁。
5. 旧 Blob 播放路径保留一个稳定发布周期，通过后端开关和前端按页开关灰度、回滚，稳定后再删除。
6. 允许且必须同步修改 Nginx 日志配置，确保 Cookie 中的媒体票据全链路不落盘。
7. 每视频票据的 2 小时配置上限不因 Cookie 容量治理而调整；单张票据仍受 Bearer 剩余寿命截断。Edge/Chrome 的本轮容量证据已达标并决定不做批量 Path 清理，Firefox 仍保留为部署前门禁。
8. 媒体会话 binding 已锁定为媒体专用 secret 对**当前原始 Bearer** 做带用途域分离的 HMAC 摘要；禁止普通裸 hash，禁止存储、记录或向 JS 暴露原 token，且不引入数据库迁移。
9. 两类媒体 Cookie 均为 host-only：设置和删除时都不发送 `Domain` 属性。
10. runtime 依赖直接锁定为 `fastapi==0.141.1`、`starlette==1.5.1`、`uvicorn==0.52.1`；dev/test 依赖锁定为 `pytest==9.0.3`（修复 CVE-2025-71176）和 `httpx2==2.12.0`。runtime 与 dev/test requirements 必须拆分，`pytest` 不得进入生产依赖；项目 `app/`、`tests/` 没有直接 `httpx` import，移除旧 `httpx` 测试依赖。
11. 媒体 master secret 至少具有 256-bit entropy；以 HMAC-SHA256 和固定版本化域分离标签分别派生 ticket JWT 签名 key、binding Cookie JWT 签名 key、原始 Bearer binding key。JWT 只允许 HS256，ticket 与 binding 使用独立 `aud`/`typ`，三种派生均以固定向量测试锁定。媒体 secret 不设新旧 key 并行窗口，轮换后旧媒体凭证立即失效。
12. 登录 Bearer 新增 `iat` 与随机 `jti`；已经签发的旧 Bearer 继续兼容至自身过期，不强制提前失效。
13. 产品预计每两小时最多访问 50 个不同视频。Edge 151、Chrome 151 的 Windows fresh profile 在 300 Cookie 压力测试后各保留 176 个动态 Path Cookie，足够本轮不实施批量 Path 清理；Firefox 因本机未安装，仍是部署前门禁，Edge/Chrome 的结果不得外推为 Firefox 或 Linux 结果。

HTTP Range 允许浏览器按媒体策略请求部分字节，但**不保证浏览器绝不下载完整文件**。浏览器仍可能顺序读取至文件末尾或扩大预取；本轮可保证的是前端不再通过 `res.blob()` 强制先接收并在 JS/Blob 中缓冲整包。

后续、非本轮事项保留为：低码率播放副本及转码、缓存/CDN、HLS，以及 MP4 Fast Start（`moov` 前置）评估。它们不得混入本轮验收或成为 HTTP Range 上线前置条件。

## 2. 当前事实与瓶颈

- 当前配置没有媒体专用 secret、票据 TTL 上限、ticket 开关、legacy Bearer 开关或媒体会话绑定配置。现有登录 token 默认有效期为 7 天；长期登录 JWT 不得进入媒体 URL，也不得直接充当媒体会话绑定 Cookie。
- 最新主线已有视频同步硬删除及应用内 `video_operation_gate`；删除会隔离并删除视频文件，当前 stream 未参与该 gate。该并发关系必须专项处理和验证。

### 2.2 前端四个入口

### 2.3 Nginx 与部署

- `deploy/nginx/mouse-annotation.conf` 当前通用 `location /api/` 执行 `auth_request /_auth`，依赖客户端 Bearer。
- 原生 `<video src>` 仅携每视频票据与媒体会话绑定 Cookie、没有 Bearer 时会先被该 Nginx 鉴权拒绝，无法到达后端。因此 stream GET/HEAD 必须有匹配优先级更高的专用 location，绕过 Nginx Bearer `auth_request`，由后端严格验证两个 Cookie。
- `POST /api/videos/{id}/stream-ticket` 仍走通用 `/api/`，由现有 Bearer + `/_auth` 保护。
- 新增的精确 `POST /api/auth/logout` 必须有位于通用 `/api/` 前的专用精确 location，绕过 Bearer `auth_request`，使 Bearer 缺失、过期或无效时仍能到达后端清除媒体会话绑定 Cookie；该例外仅限这一端点和 POST，不得扩大到其他认证 API。
- 当前部署文档将 `/api/` 描述为统一执行前置认证；实现阶段先形成候选改动，只有真实 Nginx、HTTPS、日志和浏览器证据通过后，才修正文档状态并加入已验证的 stream 例外、secret、日志脱敏和验收步骤。

## 3. 目标调用链与安全契约

### 3.1 两步调用链

1. 登录成功时，后端除返回现有登录 Bearer 外，还设置额外的媒体会话绑定 Cookie；新账号登录必须无条件先以同名、同 Path、同清理属性且不带 Domain 的过期 Cookie 清除旧值，再设置新 binding。显式注销和 401 自动登出按第 3.2 节通过专用 logout 端点闭环清理。
2. 前端使用现有长期登录 Bearer 调用 `POST /api/videos/{video_id}/stream-ticket`；后端从已验证 Bearer 取得 `sub`/`exp`，以媒体 secret 对当前原始 Bearer 做 HMAC 派生 binding。签票时从原始 Cookie header 检查 binding：零个才允许滚动升级旧会话首次设置；恰好一个时必须验证其签名、用途、时间、`sub` 与当前 Bearer 派生 binding 一致后才可续签；多于一个或已有值无效、不匹配时一律 401 且不得覆盖。
3. 后端以统一授权/路径 helper 验证用户记录、视频、active membership 和文件，在响应中 `Set-Cookie` 写入路径限定的每视频票据 Cookie；票据与 binding 的有效期均不得超过当前 Bearer 剩余寿命。响应返回不含敏感票据的 `{ url, expires_at }`，其中 `url` 是干净相对 URL `/api/videos/{video_id}/stream`。
4. 前端把该干净相对 URL 赋给原生 `<video src>`；只有这条新 Cookie stream 链路由浏览器自动携带匹配 Cookie，并自行发起普通 GET、HEAD 或多次 Range 请求。
5. 每个媒体 GET/HEAD/Range 请求都同时验证每视频票据与媒体会话绑定 Cookie 的 `sub`/binding 一致，并重新检查用户记录仍存在、实时 active membership、视频记录、请求路径和文件，而不是信任签票时的结果。

**长期登录 JWT 绝不进入 URL。** 每视频票据与媒体会话绑定值也不进入 URL；前者只能通过路径限定 Cookie 读取指定视频的 stream，后者只用于证明当前媒体登录会话，二者均不能访问其他 API。

### 3.2 票据契约

票据至少包含：

| Claim | 约束 |
|---|---|
| `sub` | 申请用户 ID |
| `video_id` | 唯一允许读取的视频 ID |
| `binding` | 媒体 secret 对当前原始 Bearer 做带用途域分离 HMAC 后的摘要；必须和媒体会话绑定 Cookie 一致 |
| `aud` | 固定媒体用途，例如 `video-stream` |
| `iat` | 签发时间 |
| `exp` | `min(iat + 7200, 当前 Bearer exp)` |
| `jti` | 可选，仅用于安全审计关联，不作为单次消费标记 |

- 每视频票据 Cookie 使用固定名称；同名 Cookie 通过精确 `Path=/api/videos/{video_id}/stream` 按视频隔离。必须设置 `Secure; HttpOnly; SameSite=Strict`，不发送 `Domain`（host-only）；票据 `exp = min(iat + 7200, bearer_exp)`，浏览器 `Max-Age` 不得晚于该实际 `exp`。续票用相同名称和 Path 覆盖该视频的旧 Cookie。生产环境必须同源 HTTPS。
- 另设固定名称的媒体会话绑定 Cookie，使用 `Secure; HttpOnly; SameSite=Strict; Path=/api/videos/`，不发送 `Domain`（host-only）。它不是长期 JWT，不取代每视频票据，不包含可直接复用的登录 token；其签名值携带 `sub`、以媒体 secret 对当前原始 Bearer 做带用途域分离 HMAC 后的 binding，以及不晚于当前 Bearer `exp` 的签名 `exp`，浏览器 `Max-Age` 同样不晚于 Bearer 剩余有效期。每个 stream 请求都必须验证 binding `exp`；不存储原 token、不写日志、不向 JS 暴露，且无需数据库迁移。登录成功时清旧值后设置新值；滚动升级旧会话仅在原始 header 中没有 binding 时允许首次设置，已有 binding 必须唯一、有效且匹配当前 Bearer，任何无效或不匹配值都不得由签票覆盖。
- 每视频票据是在“2 小时配置上限且不超过当前 Bearer 剩余寿命”内可重放的单视频持有者凭证，**不得单次使用**：浏览器可能为元数据、seek、重试和恢复对同一路径发起多次 Range。每次请求必须再由绑定 Cookie 证明它仍属于当前浏览器登录会话；任一 Cookie 缺失、过期、伪造或两者 `sub`/binding 不一致均拒绝。Bearer 到期后，即使每视频票据签名本身可验证也不得继续访问。
- 每次请求必须从**原始 Cookie header** 检测两个固定媒体 Cookie 名，不能先由会吞并重复键的普通字典解析决定分支。只有两个名字都完全不存在时，才可在 legacy 开关开启且 Bearer 有效的条件下进入 legacy 分支；legacy 关闭则拒绝。
- 原始 Cookie header 中任一个媒体 Cookie 名一旦出现，即强制进入 Cookie 分支。ticket 与 binding 必须各**恰好一个**且均通过签名、HS256 白名单、独立 `aud`/`typ`、时间和必填 claim 验证；ticket 还须验证 `video_id` 与路径参数一致。重复同名、缺少另一类、过期、伪造、格式错误、越权或两者 `sub`/binding 不匹配一律 fail closed，即使 Bearer 有效也绝不回退。
- Blob legacy 固定通过 `credentials: "omit"` 主动形成不携带 Cookie 的请求，并仅发送显式 Bearer；新 Cookie stream 不得主动省略 Cookie 后借此降级。
- 新增精确 `POST /api/auth/logout` 作为清理契约（若实施时与现有路由冲突，则按现有命名精确落位并同步全文/测试）。该端点无论 Bearer 缺失、过期或无效都幂等返回清除媒体会话绑定 Cookie 的响应，建议 `204`；它只清 Cookie，不授权或执行任何数据操作。显式注销以及前端收到任意会触发自动登出的业务 `401` 后都调用一次。前端必须设置 logout 单飞和递归保护：并发 401 复用同一清理请求，logout 自身失败或返回 401 不得再次触发 logout。HTTP 成功只能表述为“清理请求已接受”；只有真实浏览器验证旧 ticket 已不可用后，才可表述“Cookie 清理链路完成”。失败时可清本地状态并阻止继续操作，但必须保留并显示“服务端注销未完成”。
- 设置、替换和删除绑定 Cookie 必须使用相同名称、`Path=/api/videos/`、`Secure`、`HttpOnly`、`SameSite=Strict` 等属性；删除使用 `Max-Age=0`，设置和删除均不发送 `Domain`。新账号登录必须无条件先清旧同 Path Cookie再设置新 binding；不得只由前端观察 401 后假定 HttpOnly Cookie 已清除，下一次登录也必须清除/替换可能残留的 binding。不得声称 JS 能读取或删除 HttpOnly Cookie。残留每视频票据在绑定 Cookie 缺失、过期或不匹配时必须不可用。
- 每访问一个新视频会留下一个“配置上限 2 小时、并受 Bearer 剩余寿命截断”的动态 Path Cookie。产品预计每两小时最多 50 个不同视频；Edge 151、Chrome 151 Windows fresh profile 的 300 Cookie 压力测试各保留 176 个动态 Path，故本轮不做批量 Path 清理。淘汰后仍只允许统一能力单次续票；仍失败则显示可操作错误（重试签票或重新登录），不得循环。Firefox 因本机未安装而保留为部署前门禁，不得把 Windows Edge/Chrome 结果外推到 Firefox 或 Linux。
- Cookie header、两个 `Set-Cookie` 值、完整每视频票据和完整绑定值均不得写入应用日志、Nginx access/error log、Uvicorn 日志、APM、trace、metrics label、console、UI 错误或测试快照。两个 Cookie 均不得进入 URL、JS 可读存储或日志；URL 不含票据，应实现全链路不落敏感值。

### 3.3 实时授权、文件与删除语义

从现有 stream 提取唯一授权/路径 helper，供签票与取流复用。helper 必须执行：视频存在、用户记录仍存在、ProjectMembership 为 `active`、`storage_path` 非空、`Path.resolve()` 后仍位于解析后的 `videos_dir`、目标为普通文件且非空。当前 User 只检查记录是否存在，不引入其他用户状态字段。相对路径、绝对路径、`..` 和 symlink 最终都按解析后的真实边界判断。

- 不新增数据库字段，不改变表结构，**无 Alembic 迁移**。
- membership 失效或视频删除后，下一次普通/Range 请求必须立即失败；已经开始发送的响应无法承诺中途撤回，这一点在测试和运维说明中明确。
- 当前 stream 不加入公共 `video_operation_gate`，播放不得阻塞保存标注、领取/释放等正常写操作，也不扩展公共 gate 来覆盖整个 `FileResponse` 生命周期。
- 当前硬删除依赖同一文件系统内原子 `os.replace` 先隔离文件：隔离在 `FileResponse` 处理前完成时，授权 helper 返回 404；Starlette 1.5.1 实测时序为 `stat → http.response.start → open`，因此 stat 后、open 前完成隔离可能已经发出响应头，随后 body 因 open 失败而中断；文件已经打开后的行为取决于 OS，POSIX 继续读取须在 Linux 部署门禁复验。必须以该可观测契约为准，不能虚构全响应互斥或“所有未 open 请求都在发头前失败”，也不能手写 Range parser 规避。
- 若未来产品明确要求“开始响应必完整”，只能另行设计仅协调 stream 与 delete 的专用 gate；不得复用公共 `video_operation_gate`，且不属于本轮范围。

## 4. 后端实施要求

1. **统一 helper**：集中实时授权、路径解析、文件检查和稳定错误映射；签票与 stream 禁止维护两套规则。
2. **密码学与登录会话绑定**：媒体 master secret 至少具有 256-bit entropy。固定使用 HMAC-SHA256，以版本化域分离标签 `mouse-annotation/media/ticket-jwt/v1`、`mouse-annotation/media/binding-jwt/v1`、`mouse-annotation/media/raw-bearer-binding/v1` 分别派生 ticket JWT 签名 key、binding Cookie JWT 签名 key 和原始 Bearer binding key；禁止普通裸 hash，禁止存储/记录原 token 或向 JS 暴露 token/binding。两个 JWT 只接受 HS256，并使用互不相同的固定 `aud`/`typ`；派生与签名必须有固定向量测试。登录 Bearer 新增 `iat` 和密码学安全随机 `jti`，旧 Bearer 兼容至过期。登录成功设置 binding；新账号登录无条件先清旧同 Path、host-only Cookie 再设置。滚动升级签票仅在 binding 名零次出现时允许首次设置；恰好一次时必须完整验证并匹配当前 Bearer，多次、无效或不匹配时 401 且不得覆盖。签名 payload 的 `exp` 和 Cookie `Max-Age` 不晚于 Bearer 剩余寿命，每个 stream 请求验证 binding `exp`，且无数据库迁移。媒体 secret 不设双 key 窗口，轮换立即使旧 ticket 与 binding 失效。
3. **签票 API**：新增响应 schema 与 `POST /api/videos/{video_id}/stream-ticket`；仅接受现有 Bearer，从其取得 `sub`/`exp` 并派生 binding。以 `Set-Cookie` 设置/覆盖 binding 与每视频票据 Cookie，票据 `exp = min(iat + 7200, bearer_exp)` 且两类 Cookie 的 `Max-Age` 均不得超过各自实际剩余有效期；返回干净相对同源 URL 与 UTC `expires_at`。响应 JSON 和日志均不得包含任一 Cookie 值。
4. **三态 stream 分支**：从原始 Cookie header 检测两个固定媒体 Cookie 名。两者都不存在时，才允许由 legacy 开关 + 有效 Bearer 进入 legacy；任一名字出现就强制 Cookie 分支，且 ticket、binding 必须各恰好一个并均有效。重复同名、缺一、过期、伪造、格式错误或不匹配全部 fail closed，禁止回退 Bearer。正常响应继续 `inline FileResponse`，设置 `Cache-Control: private, no-store`，避免撤权后由共享缓存继续供给字节。
5. **显式 HEAD**：后端必须显式注册 `HEAD /api/videos/{video_id}/stream`，复用 GET 的 Cookie/legacy 鉴权、绑定验证及统一文件 helper，返回与 GET 一致的元数据头且 body 为空；禁止依赖隐式路由或把 405 视作可接受语义。按 Starlette 1.5.1 实测，无 Range 为 200、带可满足 Range 为 206，body 均为空；`If-Range` 与相关头按第 4 节锁定契约测试。
6. **依赖锁定**：runtime requirements 直接锁定 `fastapi==0.141.1`、`starlette==1.5.1`、`uvicorn==0.52.1`；dev/test requirements 锁定 `pytest==9.0.3`（修复 CVE-2025-71176）和 `httpx2==2.12.0`。拆分 runtime 与 dev/test requirements，生产依赖不得包含 pytest。因 `app/`、`tests/` 均无直接 `httpx` import，移除旧 `httpx` 测试依赖。Python 3.10 完整 resolved constraints 已保存；Linux resolved lock 已在服务器隔离候选中生成并验证。不能保留宽范围后声称能力已锁定，也不能手写 Range parser。
7. **配置**：增加 7200 秒 TTL 配置上限、固定且相互独立的 ticket/binding `aud` 与 `typ`、每视频票据与媒体会话绑定的固定 Cookie 名称/Path、生产必填媒体 master secret、ticket enabled 和 legacy Bearer enabled。三种派生固定为第 2 项的 HMAC-SHA256 版本化标签，不提供算法、模式或双 key 切换。生产校验必须拒绝默认值、占位值、空值和低于 256-bit entropy 的 secret；真实 secret 不提交仓库。
8. **可达注销清理**：新增精确 `POST /api/auth/logout`；不依赖有效 Bearer，无论 Bearer 缺失、过期或无效都幂等清除 binding Cookie（建议 `204`），且不得借此授权任何数据操作。设置/删除均为 host-only，不发送 `Domain`，删除的名称、Path 和安全属性与设置一致。
9. **容量治理**：本轮基于“每两小时最多 50 个不同视频”以及 Edge 151、Chrome 151 Windows fresh profile 在 300 Cookie 压力下各保留 176 个动态 Path 的证据，决定不实现服务端批量 Path 清理。保留淘汰后的单次续票与可操作错误；Firefox 实测仍是部署前门禁。
10. **删除并发**：不修改公共 operation gate；以真实框架和同文件系统原子隔离记录三段可观测契约：隔离先于 `FileResponse` 处理时 helper 404；stat 后、open 前隔离可能已发头后中断；open 后由 OS 语义决定，并在 Linux 部署门禁复验 POSIX 已打开 FD 可继续读取。

Starlette 1.5.1 协议实测已锁定：无 Range 为 `200`；单 Range、开放范围、后缀范围与多 Range 为 `206`；超界为 `416`；倒序或畸形 Range 为 `400`；`If-Range` 匹配为 `206`、不匹配为 `200`；显式 HEAD 无 Range 为 `200`、带可满足 Range 为 `206`，body 均为空。业务代码不得二次加工这些语义或手写 Range parser。

## 5. Nginx 与日志实施要求

配置改动在开发阶段只能称为“候选配置”，通过 `nginx -t` 和真实代理验收后才能称为已完成。部署阶段须逐项确认：

1. 新增仅匹配 `^/api/videos/[0-9]+/stream$` 的媒体专用正则 location，并把它写在配置中所有可能重叠的正则 location 之前；它应精确锚定路径并优先于普通 `location /api/`。不得把通用 `/api/` 改成会压过媒体正则的 `^~`，也不得扩大为其他 API。
2. 媒体专用 location 仅允许 GET/HEAD，其他方法拒绝；**不执行** `auth_request /_auth`，也不把缺失 Bearer 当作错误，请求必须代理到后端，由后端同时验证每视频票据与媒体会话绑定 Cookie。后端显式 HEAD 路由必须经代理返回成功（无 Range 为 200、body 为空），不得由 Nginx 将 HEAD 改写成 GET 或接受 405；stream-ticket POST 不匹配该 location，继续走通用 Bearer 鉴权。
3. 在通用 `/api/` location 前增加 `location = /api/auth/logout`（若现有路由冲突则使用实施时锁定的同一精确路径），仅允许 POST，其他方法拒绝；该 location 绕过 `auth_request /_auth` 并代理到幂等清理端点。精确路径与方法限制必须同时验证，不得让其他 `/api/auth/*`、其他 API 或 logout 的其他方法绕过 Bearer 前置鉴权。
4. 不使用 `proxy_force_ranges`，不手工拼接 `Range`/`If-Range` 请求头或 Range 响应头。验证 Nginx 默认代理行为没有丢弃或改写这些头，以及 `Accept-Ranges`、`Content-Range`、`Content-Length`、`ETag`/`Last-Modified`（以锁定版本实际提供为准），206 不得变为 200。
5. 媒体 location 显式设置 `proxy_buffering off; gzip off;`，确保不整包缓冲、不压缩媒体且客户端断开可传播至上游。验收 Nginx、Uvicorn 的内存和临时盘不会随完整文件增长。
6. 在 Nginx `http` 层定义媒体专用 `log_format`，只记录 `$uri` 及必要的非敏感字段；禁止 `$request`、`$request_uri`、`$args` 和 `$http_cookie`。媒体 location 必须通过 `access_log` 显式使用该格式；同时确保 Nginx/Uvicorn/应用均不记录 Cookie header、每视频票据 Cookie、媒体会话绑定 Cookie 或任一 `Set-Cookie` 值，并检查 error log、systemd journal、APM/trace。该日志配置改动是本轮必做项。
7. 部署前用候选配置执行 `nginx -t`；通过后才 reload。用无 Bearer、由浏览器自动携带每视频票据与绑定 Cookie 的干净 stream URL 经公网同源 HTTPS 验证，而非只测后端直连；另须经真实 Nginx 验证“过期 Bearer → 业务 401 → 精确 POST logout → `Set-Cookie` 的 `Max-Age=0` → 旧 ticket 不可用”完整链路。

本文不提供未经实际版本验证的完整 Nginx 伪配置；实现 PR 必须同时提交配置测试或可复现的代理验收证据。

Nginx 候选配置的静态测试由 backend 测试套件拥有；跨层部署/运维文档只能在相应真实 Nginx 证据通过后更新状态，不得用静态测试把代理能力写成已完成。

## 6. 前端统一能力与四入口迁移

新增统一流媒体 API/hook（最终名称按现有项目约定确定），职责包括签票、加载世代、媒体错误单次续票、状态恢复和脱敏错误。四个页面不得各复制一套状态机。

### 6.1 能力层契约

- 用 `apiFetch`/Bearer 请求 stream-ticket，只读取不含票据的 JSON，不读取视频 body；原生 `<video src>` 使用返回的干净相对 URL。新 Cookie stream 才允许浏览器自动携带媒体 Cookie；两个 Cookie 均由浏览器管理，不进 JS、localStorage/sessionStorage、路由或 analytics。
- 旧 `fetchVideoStreamUrl`/Blob legacy 请求必须显式使用 `credentials: "omit"`，只发送显式 `Authorization: Bearer ...`，不得携带每视频票据或媒体会话绑定 Cookie。这样残留的有效、过期或伪造媒体 Cookie 都不能阻断 Blob 回滚；该要求只隔离 legacy 请求，绝不放松 Cookie stream 中“Cookie 无效不得回退 Bearer”的后端规则。
- `AbortController` 只取消签票 fetch，不承诺取消媒体元素自行发出的 GET/HEAD/Range。切换、关闭、卸载及续票换 URL 必须严格按顺序执行：①先将旧世代置为失效且清空当前引用，并 abort 其签票 fetch；②解绑旧媒体事件监听，或以已失效世代屏蔽所有旧回调；③再对旧媒体执行 `pause()`、移除 `src`、调用 `load()` 终止请求；④清理完成后才建立并发布新世代。`pause()`/`load()` 同步触发或 abort/error/emptied 延迟触发的任何旧事件都不得续票、恢复媒体状态或回写当前 UI；旧签票响应即使稍后完成也必须忽略。
- 每个加载世代初始签票一次。票据过期或任意媒体 `error` 时，每个世代**最多自动续票一次**，防止循环。
- 续票前保存目标 video ID、`currentTime` 和播放/暂停状态；新 URL 完成 metadata/canplay 后恢复时间，原先播放则尝试恢复播放，原先暂停则保持暂停。切换到新视频/片段创建新世代并重置续票额度。
- 原生媒体错误通常没有可靠 HTTP 状态，不根据 `MediaError` 猜测 401/403。只有签票 API 错误按 401/403/404 分类；401 保持现有登出行为。
- 显式注销和任意触发自动登出的业务 401 都以允许浏览器处理 Cookie 的同源请求调用一次精确 `POST /api/auth/logout`。注销协调器必须单飞：并发 401 共享同一请求，并设置递归保护，使 logout 自身失败或返回 401 不再触发 logout。HTTP 成功只标记“清理请求已接受”；必须在真实浏览器中继续验证旧 ticket 不可用，之后才标记“Cookie 清理链路完成”。网络错误、非成功状态或旧 ticket 仍可用时保留“服务端注销未完成”。该协调器不读取 `Set-Cookie`，也不尝试由 JS 读取或删除 HttpOnly Cookie。
- UI 仅给出脱敏的可行动错误；UI、console 和日志不包含 Cookie、媒体票据或媒体元素的完整 `currentSrc`。
- 生产同源 HTTPS 是硬门禁，不能为了开发调试降低 `Secure`、`HttpOnly` 或 `SameSite=Strict`。本地跨端口如需验证，必须使用受控 HTTPS 测试域名/证书，签票 fetch 显式采用所需 credentials，并为精确测试 origin 配置 CORS credentials；记录该配置且不得带入生产宽松策略。

### 6.2 四入口灰度

四处 `<video>` 均设置 `preload="metadata"`（仅为浏览器提示），并接入统一能力：

1. `VideoPreviewDialog`：关闭、Escape、切换预览时取消旧世代；保留现有焦点管理和 controls。
2. `ClipsPage`：保留加载后定位 `start_time`、自动播放尝试、`end_time` 停止和重复点击回到起点。
3. `ReviewPage`：保留视频选择世代、标注快照、检测叠加、逐帧和审核操作。
4. `AnnotatePage`：保留 `?t=` 定位、时间轴、帧步进、检测叠加、快捷键和相邻视频导航；删除当前把 `streamUrl` 拼入错误信息的行为。

迁移期间保留 `fetchVideoStreamUrl` 及其 object URL 清理，只供关闭新能力的页面回滚，并强制该 legacy fetch 使用 `credentials: "omit"` + 显式 Bearer。不得误删缩略图和 ZIP 下载等仍合理使用 Blob 的代码。稳定周期结束后才删除视频专用 Blob API 和四入口遗留分支。

## 8. 测试与验收矩阵

### 8.1 HTTP/Range 协议

- 无 Range：`200`、完整内容、正确 `Content-Length`/媒体类型、`Accept-Ranges: bytes`、inline、`private, no-store`。
- `bytes=0-0`、`bytes=N-M`：`206`，字节、`Content-Range`、`Content-Length` 精确。
- 开放范围 `bytes=N-`、后缀范围 `bytes=-N`：`206` 且边界正确。
- 超界范围：`416`，断言锁定版本实际 `Content-Range`。
- 多 Range：Starlette 1.5.1 实测 `206`；倒序和畸形 Range 实测 `400`；断言实际 body 与相关头，不得退化成整包 `200`。
- `If-Range` 匹配实测 `206`，不匹配实测 `200`。
- 显式 HEAD 路由复用 GET 鉴权/helper：无 Range 为 `200`，带可满足 Range 为 `206`，body 均为空；断言 `Content-Length`、媒体类型、`Accept-Ranges`、缓存、validator 与 Range 相关头符合 Starlette 1.5.1 实测契约。任何场景都不得接受 405。
- 客户端中断、连续 seek、并行 Range 后文件句柄和响应资源正确释放。

### 8.2 票据、权限与降级

- 登录成功设置媒体会话绑定 Cookie；滚动升级旧会话签票时，原始 header 中零个 binding 才允许首次设置，恰好一个必须有效且匹配当前 Bearer，多于一个或已有值无效、不匹配均 401 且不得返回任何 `Set-Cookie`；正常签票/取流。分别断言绑定 Cookie 的 `Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/api/videos/`，以及每视频 Cookie 的相同安全属性和精确 Path；设置与删除两类响应都断言**没有 `Domain` 属性**（host-only），删除名称、Path 和其他清理属性一致。响应 JSON 只有干净相对 URL 和 `expires_at`、不含任一票据/binding。
- 分别以 Bearer 剩余寿命大于、小于和恰好等于 7200 秒签票，断言 ticket `exp = min(iat + 7200, bearer_exp)`、ticket `Max-Age` 不晚于实际 `exp`，binding 签名 `exp` 与 `Max-Age` 不晚于 Bearer `exp`；推进时间到 Bearer 到期后，每个 stream 请求均因 ticket/binding 过期被拒绝，不允许已签 ticket 延长访问。
- 用固定向量分别验证至少 256-bit entropy 的媒体 master secret 经三个固定版本化标签和 HMAC-SHA256 派生 ticket JWT key、binding JWT key 与原始 Bearer binding key；验证 binding 针对**原始 Bearer**而非普通裸 hash。两个 JWT 仅允许 HS256，并验证独立 `aud`/`typ`；断言数据库、应用状态、日志、响应 JSON、JS 存储和快照中均无原始 Bearer 或完整 binding。
- 新登录 Bearer 必须包含 `iat` 和随机 `jti`；旧格式 Bearer 在原 `exp` 前仍可签票/访问，过期后拒绝。媒体 secret 轮换后旧 ticket/binding 立即失效，测试不得保留双 key 验证窗口。
- 同名 Cookie 的视频 Path 隔离；同视频续票以相同名称/Path 覆盖旧 Cookie；过期、伪造签名、错误算法、错误 `aud`、未来 `iat`、错误/缺失 claim 均拒绝。
- ticket 用户记录已删除、非成员、inactive membership、跨项目；ticket `video_id` 与请求路径不一致；binding/session claim 缺失或错误。
- 直接构造原始 Cookie header 覆盖三态：两个固定名字都不存在时，legacy 开关 + 有效 Bearer 才可成功；任一个名字出现即进入 Cookie 分支。分别覆盖 ticket/binding 各恰好一个成功，以及重复 ticket、重复 binding、只带任一个、过期、伪造、格式错误和不匹配均拒绝；即使同时有有效 Bearer 也绝不降级。
- legacy Blob 集成测试断言 `credentials: "omit"` 且只有显式 Bearer；浏览器中分别残留有效、过期、伪造的每视频/绑定 Cookie 时，回滚请求均不发送 Cookie 并成功。该成功不得改成服务端接受无效 Cookie 后降级 Bearer。
- 精确 `POST /api/auth/logout` 分别在 Bearer 缺失、过期、无效和有效时幂等成功（建议 204），均以同名、同 `Path=/api/videos/`、同安全属性、无 `Domain`、`Max-Age=0` 请求清除旧 binding；断言它不授权或执行任何数据操作，其他方法和其他 auth API 不获得绕过。HTTP 成功只证明“清理请求已接受”；真实浏览器后续验证旧每视频 ticket 在 binding 缺失时不可用，才证明 Cookie 清理链路完成。
- 显式注销、任意自动登出业务 401 和账号切换覆盖 logout 单飞与递归保护：并发 401 只发一次 logout；logout 失败或自身 401 不再次调用。覆盖离线/失败清理后本地状态已清但保留“服务端注销未完成”，以及下一次登录无条件先清旧同 Path、host-only Cookie再设置新 binding；测试不得用 JS 删除 HttpOnly Cookie 伪造闭环。响应成功只标记“清理请求已接受”，真实浏览器验证旧 ticket 不可用后才标记链路完成。
- 同浏览器 A→B 切换覆盖旧 ticket + 新 binding、旧 binding + 新 ticket，均拒绝；新 ticket + 新 binding 才成功。
- 签票后删除 membership 或置 inactive，下一次 Range 立即失败；签票后视频硬删除，下一次请求失败。
- 票据重复用于多个合法 Range 成功，证明不是单次票据。
- 保留 Gate 1 证据：产品预计每两小时最多 50 个不同视频；Edge 151、Chrome 151 Windows fresh profile 在 300 Cookie 压力测试后各保留 176 个动态 Path，因此本轮不做批量 Path 清理。发生淘汰后统一能力最多单次续票，否则显示包含“重试签票/重新登录”的可操作错误。部署前另测 Firefox；不得声称现有结果代表 Firefox 或 Linux。

### 8.3 路径、文件与删除并发

- 合法相对/绝对路径；`..`、绝对越界、symlink 越界、目录、文件缺失、零字节均拒绝。
- 多个媒体读请求可并行且不阻塞保存标注、领取/释放等正常写操作；当前 stream 不进入公共 `video_operation_gate`。
- 并发硬删除验证同文件系统原子 `os.replace`：隔离先于 `FileResponse` 处理时 helper 404；Starlette 1.5.1 在 stat 后先发送 `http.response.start` 再 open，故两者之间隔离可表现为已发头后 body 中断；open 后按 OS 语义处理，POSIX 已打开 FD 继续读取保留为 Linux 部署门禁。测试和文档不得把该边界简化为“所有未 open 请求都在发头前失败”。
- 客户端中断后文件句柄正确释放；删除后的 DB、manifest/quarantine 和文件状态符合既有硬删除契约。
- membership 失效与在途响应并发：在途响应按既定限制处理，之后每个新请求均拒绝。

## 9. 部署与回滚

### 9.1 部署顺序

1. 在任何 P1 后端或 Nginx 改动前，先构建、保存并部署 legacy 强制 `credentials: "omit"` 的 Blob 前端制品，逐一验证四入口走 Blob 且不发送 Cookie；该制品作为 P1—P3 固定回滚前端。若开关是构建时变量，回滚只能部署对应制品，不能视作即时按页操作。
2. 生成至少具有 256-bit entropy 的媒体 master secret，并写入 release 外、权限 `0600` 的稳定生产环境文件；由三个固定版本化 HMAC-SHA256 标签派生独立用途 key。部署包含登录 Bearer `iat`/随机 `jti`（兼容旧 Bearer 至过期）、精确幂等 logout/401 自动注销/切换 binding Cookie 闭环及 Bearer 有效期截断的后端三态 stream，legacy 保持开启。secret 无双 key 窗口，轮换会立即废止全部旧媒体凭证。
3. 生产仅安装 runtime requirements；dev/test requirements 单独安装。使用服务器隔离候选已验证并保存的 Python 3.10 Linux resolved lock；该候选的 `pip check` 与完整后端测试已经通过。`pytest` 不进入生产依赖。跑迁移命令仅作现有 schema 一致性检查，本功能本身无迁移。
4. 后端直连验证两个 `Set-Cookie` 的 host-only/同 Path 清理属性、密码学固定向量、Bearer 有效期截断、Path 隔离/覆盖续票、原始 Cookie header 三态 fail closed、Starlette 1.5.1 的 200/206/400/416/If-Range/显式 HEAD 契约和删除并发。HTTP logout 成功在此只能记为“清理请求已接受”。
5. backend 所有的 Nginx 静态测试通过后，安装候选 Nginx 配置和媒体专用脱敏日志格式，先 `nginx -t`，通过后 reload；验证公网同源 HTTPS、双 Cookie 取流、GET/HEAD 契约一致、仅精确 POST logout 绕过 `auth_request`、真实浏览器中旧 ticket 不可用的注销清理链路和全链路日志脱敏。禁止采用从 `auth_request` 转发 `Set-Cookie` 的复杂方案。真实 Nginx、真实浏览器 logout、HTTPS/日志、Firefox 和约 2 GB 量化仍属于集成/部署门禁，不属于 P1 candidate ready。
6. 部署带按页开关的新流媒体前端，按 P3 顺序灰度。每页观察错误率、206、Cookie 淘汰/续票、传输量和业务回归；此前保存的 omit Blob 制品必须保持可部署。
7. 稳定发布周期结束并完成回滚演练后进入 P4；此前不得删除旧 Blob 或关闭 legacy。

各层证据通过时再更新其 owning 文档：实现证据可更新后端/前端说明，真实 Nginx、HTTPS、日志和浏览器证据通过后才更新跨层 `deploy/README.md`、`deploy/部署复盘与运维指南.md` 及本计划状态；只记录已验证事实。若实际服务器配置已确认变更，再按服务器文件清单规则更新对应清单。

### 9.2 回滚方案

- **所有 P1—P3 及 Nginx 故障统一按固定顺序回滚，不得颠倒**：①确认后端 legacy Bearer 已开启且可用；②切换或部署已具备 `credentials: "omit"` 的 Blob 前端；③逐一验证四入口确实走 Blob，且浏览器残留的有效、过期或伪造媒体 Cookie 均未随请求发送；④完成前三步后，才允许关闭 ticket、安装并经 `nginx -t` 验证上一版 Nginx 配置、回滚后端。不得先关闭 ticket、撤掉专用 location 或回滚后端，再让仍使用干净 stream URL 的前端承受故障窗口。
- 若前端开关是构建时配置，必须在上线前保存并部署验证可回滚 Blob 前端制品；回滚时部署该制品，不能描述成即时按页切换。运行时按页开关也必须完成四入口验证后才能进入第④步。
- 依赖行为回归时恢复已验证的精确 lock/constraints，禁止现场手写 Range parser。
- 本功能无数据库变化，无数据库 downgrade。媒体 secret 不设双 key 窗口；轮换时只启用全新 secret，并接受旧 ticket 与旧 binding 立即失效，不恢复旧 secret 以免旧媒体凭证重新生效。
- 绑定 Cookie 的发布/回滚必须与登录、注销、401 自动登出和账号切换端点配套；不得部署只能设置、不能由后端同 Path 清除的组合。回滚不依赖 JS 删除 HttpOnly Cookie，残留绑定或每视频票据不能绕过双 Cookie 一致性校验。
- P4 删除旧路径后，单开 legacy 不足以恢复前端播放；必须整体切回保留的上一版前后端制品及对应 Nginx 配置，且该上一版 Blob 请求已满足 `credentials: "omit"`。

## 10. 完成定义（DoD）

- 四入口均通过统一能力使用原生干净相对 stream URL，设置 `preload="metadata"`，新播放链路不再执行 `res.blob()`；回滚用 Blob legacy 明确以 `credentials: "omit"` 只发送 Bearer，并在残留有效、过期、伪造媒体 Cookie 下验证成功。
- Secure + HttpOnly + SameSite=Strict 的 host-only 每视频票据 Cookie 与 `Path=/api/videos/` 的 host-only 媒体会话绑定 Cookie 完成双 Cookie `sub`/binding 一致性验证；从原始 Cookie header 执行三态规则，任一固定名字出现即要求两者各恰好一个，重复、缺一或无效均 fail closed。binding 固定为至少 256-bit entropy 的媒体 master secret 经版本化 HMAC-SHA256 域分离后对原始 Bearer 的摘要，两个 JWT 只允许 HS256 且使用独立 `aud`/`typ`；签名 `exp`/Max-Age 不晚于 Bearer 到期。每视频票据配置上限 7200 秒且 `exp = min(iat + 7200, bearer_exp)`，限单视频/用途并可多 Range 重放。Bearer 到期后旧票据不可用；设置/删除无 `Domain`，并完成固定向量、隔离/续票、Cookie 无效禁止降级和双 Cookie 脱敏测试。长期 JWT、媒体票据和 binding 从未进入 URL、JS、数据库或日志。
- 新登录 Bearer 包含 `iat`/随机 `jti`，旧 Bearer 兼容至过期；登录成功、精确 `POST /api/auth/logout`、显式注销、任意业务 401 自动登出、离线/失败清理后的下一次登录及同浏览器账号切换测试闭环。logout 在无效/缺失/过期 Bearer 下可达且幂等，只清 Cookie、不授权数据操作，前端具备单飞/递归保护。HTTP 成功仅标记“清理请求已接受”；真实浏览器证明旧 ticket 不可用后才标记“Cookie 清理链路完成”。旧 ticket + 新 binding、旧 binding + 新 ticket 均不可用，失败保留“服务端注销未完成”，未以清 `localStorage` 或 JS 删除 HttpOnly Cookie 代替。
- runtime 精确锁定 FastAPI 0.141.1、Starlette 1.5.1、Uvicorn 0.52.1，dev/test 精确锁定 pytest 9.0.3 和 httpx2 2.12.0；requirements 已拆分、生产不含 pytest、旧 httpx 依赖已移除。Python 3.10 完整 constraints 已保存，Linux resolved lock、`pip check` 与完整后端回归已在服务器隔离候选中验证。显式 HEAD 200/206 且 body 为空；GET 的 200、单/open/suffix/多 Range 206、超界 416、倒序/畸形 400、If-Range match 206/mismatch 200 均按锁定版本验证，业务代码没有 Range parser。
- 路径/symlink、membership 失效、硬删除原子隔离与实测竞态契约通过；播放不进入公共 operation gate 且无数据库迁移。
- Nginx 专用 stream location、GET/HEAD 限制、精确 POST logout 专用 location、其他 auth/API 不绕过、默认头部代理、无整包缓冲、媒体不压缩和不含 Cookie/query 的媒体日志均经真实代理验证；“过期 Bearer → 业务 401 → logout → `Set-Cookie Max-Age=0` → 旧 ticket 不可用”集成测试通过，且未采用从 `auth_request` 转发 `Set-Cookie`。

- 严格取消顺序及同步/延迟 abort/error/emptied 测试通过；旧事件与响应均不能续票、恢复状态或回写当前世代。
- P1—P3 和 Nginx 故障均按“确认 legacy → 部署 omit Blob 前端 → 验证四入口走 Blob 且不发 Cookie → 再关闭 ticket/回滚 Nginx 与后端”顺序演练成功；构建时开关已有预存且部署验证的回滚制品。旧 Blob 保留满一个稳定发布周期后才完成 P4 删除。
- secret 轮换演练证明无双 key 窗口、旧 secret 不恢复，轮换后旧 ticket 与 binding 立即失效。
- 所有部署、运维和项目状态文档与已验证实现一致，完整每视频票据、完整 binding 和 Cookie header 在所有日志和错误渠道中的出现次数为 0。
