# 播放与带宽优化计划

> **状态：规划，未实施。** 本文仅恢复并集中记录生产部署前的带宽优化方向，不表示当前系统已具备这些能力；实施状态须以代码、测试和部署验收为准。

## 计划方向

1. 视频播放改为 HTTP Range 流式；当前前端整包下载 blob，单次打开即下载整个文件。
2. 增加播放用低码率副本：保留存储母版，标注和审核使用转码后的低码率版本，例如 H.264 CRF 28–30 或 H.265；Firefox 桌面不支持 HEVC 时需要回退方案。
3. 增加缓存：为视频与缩略图设置浏览器缓存头（`Cache-Control` / `ETag`），并在反向代理层使用 `proxy_cache` 或 CDN，减少多人重复观看同一视频的传输。
4. 优化前端加载策略：视频使用 `preload="metadata"`，缩略图懒加载并压缩为 WebP，同时修复前端 `/thumbnails/` 没有对应后端路由的问题。
5. 按需异步生成播放版本，复用现有 MediaWorker 队列，避免预先转码全部视频。

以上五项均待后续排期、实现和验收。
