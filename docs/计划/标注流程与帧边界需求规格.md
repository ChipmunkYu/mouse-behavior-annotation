# 标注流程与帧边界需求规格

> 状态：需求已确认，尚未实现
> 日期：2026-08-22
> 基线：`origin/main@59965e3`
> 对应工作项：WI-20260805-22

## 1. 背景

当前新建行为流程由 `S` 设置起点、`D` 设置终点并立即创建标注。类别、参与对象、起点和终点存在隐含填写顺序；设置起点后，时间轴没有独立的未保存标志；结束时间使用 `round(time × fps)` 得到 inclusive `end_frame`，而媒体层又把 inclusive 结束帧转换为 `(end_frame + 1) / fps`，两种语义在帧边界处可能不一致。

本规格将新建行为改为显式“未保存行为草稿”：各字段可按任意顺序填写，点位设置不自动提交，点击“保存此行为”时才统一校验并创建标注。同时统一时间、帧和媒体区间的权威关系。

## 2. 已确认目标

1. 设置开始点后，时间轴必须立即在对应位置显示清晰的开始标志。
2. 类别、开始点、结束点和参与对象不强制填写顺序。
3. 页面增加明确的主操作按钮“保存此行为”。
4. 设置结束点只更新草稿，不自动创建标注。
5. 只有点击“保存此行为”时，才要求当前行为所需信息全部齐全并统一校验。
6. 校验失败不得清空用户已经填写的草稿信息。
7. 每个所选参与 ID 只需分别在双端 inclusive 行为区间内至少有一帧未抑制有效检测；不要求参与 ID 共同出现，也不要求覆盖首尾或达到覆盖率。
8. 多条行为允许任意重叠，包括同类别、不同类别以及同一参与 ID；不做通用互斥校验。
9. 不允许单帧行为，必须满足 `end_frame > start_frame`，即至少覆盖两个帧索引。
10. 帧是区间唯一权威；时间由帧与 FPS 统一派生，界面只读显示时间，不提供独立秒输入。
11. 保存成功后只保留类别，清空起止点、参与对象及其他草稿字段，开始新的未保存行为状态。
12. `Ctrl+Enter` 保存完整行为草稿，并与“保存此行为”按钮复用完全相同的校验、确认和 API 路径；普通 `Enter` 不保存。
13. 草稿清理操作统一称为“重置标注”，且必须经用户确认。
14. 同一视频切换到 track 修正模式时保留草稿，返回行为标注模式时完整恢复，不触发离开确认。
15. 时间轴不显示独立结束点标志；开始点持续显示，起止点齐全时显示草稿区间。

## 3. 未保存行为草稿

### 3.1 草稿字段

每个视频同一时刻最多存在一个本地未保存行为草稿，包含：

- 行为类别；
- 开始点；
- 结束点；
- 无序类别的已选 track ID，或角色类别的参与对象角色分配；
- 可信度及后续纳入新建表单的其他字段；
- 根据点位实时派生的帧、时间与完整性状态。

“未保存行为草稿”只存在于当前前端页面，不等同于 `Video.workflow_status=draft`，也不写入 Annotation API。

任一字段发生变化即建立草稿。字段彼此独立，用户可以：

- 先设置开始点或结束点；
- 先选择类别；
- 先选择参与对象；
- 在保存前任意修改其中一项，而不清空其他已兼容字段。

### 3.2 草稿状态摘要

页面持续显示紧凑摘要，例如：

```text
未保存行为 · 类别 ✓ · 开始 ✓ · 结束 — · 参与对象 2
```

字段未补齐时使用中性“待补齐”状态，不提前弹出错误或阻止填写其他字段。仅明显无效但仍可修正的状态使用警示，例如结束点早于开始点。

### 3.3 类别与参与对象

- 未选择类别时仍允许选择 track；选择无序类别后直接使用已选 track，再按该类别人数约束校验。
- 切换类别不得静默丢弃已选 track。
- 从无序类别切换到角色类别时，无法自动确定角色的 track 进入“待分配”状态，由用户分配到角色槽位。
- 从角色类别切换到无序类别时，可保留角色分配中 track 的去重并集。
- 类别人数或角色规则不满足时，不阻止继续设置点位，只在草稿状态和保存校验中提示。
- 每个所选参与 ID 分别校验：其在 `[start_frame, end_frame]` 内至少有一帧未抑制有效检测即可。不同参与 ID 无须在同一帧共同出现，也无须覆盖区间首尾或满足检测覆盖率。

### 3.4 行为区间重叠

- 多条行为可任意重叠，无论类别相同或不同、参与 ID 相同或不同。
- 保存、提交与导出均不做通用行为互斥校验；仅执行类别自身人数、角色及其他明确业务约束。

## 4. 时间轴交互

### 4.1 草稿标志

- 设置开始点后，时间轴立即显示“开始”标志。
- 时间轴不绘制独立“结束”标志。开始点无论结束点是否设置都持续显示，并通过形状、标签和颜色共同表达，不得仅依赖颜色。
- 开始点和结束点都已设置时，显示二者之间的草稿区间，但不另绘制与开始点对称的结束标志。
- 只有开始点时只显示开始标志；只有结束点时，时间轴不绘制结束标志或虚构区间，仅在草稿摘要中明确显示“结束已设、开始待补齐”。
- 未选择类别时使用固定中性色；选择类别后可采用类别颜色，但草稿区间保持虚线或半透明，以区别已保存标注。
- 再次执行“设开始”或“设结束”只替换对应点，不改变类别和参与对象。
- 结束点早于或等于开始点时保留开始标志，不绘制无效草稿区间，并在草稿摘要中标记“区间待修正”；点击保存时拒绝。

### 4.2 时间轴操作边界

- 点击时间轴只移动播放头，不自动修改开始点或结束点。
- 草稿点位必须来自显式“设开始”“设结束”按钮或对应快捷键。
- 时间轴状态栏显示已经固定的草稿开始/结束，不得以当前播放时间冒充尚未设置或已经设置的结束点。
- 已保存标注区间保持原有实色展示；未保存草稿始终具有独立视觉层级。

### 4.3 可访问性

- 时间轴可访问说明应包含播放位置与草稿信息，例如“当前 00:12.340；草稿开始 00:08.200；结束未设置”。
- 开始点和草稿区间同时使用文字/形状/线型辅助颜色；结束状态由草稿摘要文字明确表达。
- 草稿点位变化通过 `aria-live="polite"` 宣布。
- 窄屏时开始标志可以缩短文字，但“开始”语义仍必须可辨识；结束点设置状态仍须在草稿摘要中可辨识。

## 5. “保存此行为”

### 5.1 按钮行为

- 在点位操作区提供主按钮“保存此行为”。
- 草稿不完整时按钮仍可点击，以便一次展示所有缺失项。
- 仅在页面只读且当前角色无写权限、保存请求进行中或其他不可恢复的写入门禁占用时禁用。对于允许通过既有确认退回草稿后编辑的工作流状态，按钮保持可用并在校验通过后进入确认流程。
- 保存期间显示“保存中…”，防止重复提交。
- 设置结束点不再隐式调用创建 Annotation API。

### 5.2 保存时统一校验

点击保存时一次检查：

1. 已选择有效行为类别；
2. 开始点和结束点均已设置并位于视频范围内；
3. `end_frame > start_frame`，区间至少覆盖两个帧索引；
4. 无序类别参与对象数量满足类别约束；
5. 角色类别所有必需角色已补齐，且同一 track 未跨角色重复；
6. 每个所选参与 ID 分别在区间内至少有一帧未抑制有效检测；
7. 当前检测导入、identity revision、Annotation version 和视频工作流仍满足写入条件。

行为区间与既有行为重叠不构成校验错误。

校验失败时：

- 不发送创建请求；
- 不清空草稿；
- 在保存按钮附近展示错误摘要；
- 一次展示所有能够确定的问题；
- 对相关区域设置错误状态，并把焦点移到第一个未完成项。

校验通过后，若当前视频不是可直接编辑状态，再执行既有工作流影响确认。用户取消确认时保留完整草稿。请求失败同样保留草稿并允许重试。

保存成功后，将草稿区间转换为已保存标注区间，并通过状态提示与 `aria-live` 宣布“行为已保存”。随后只保留类别，清空开始点、结束点、参与对象（含角色分配）、可信度及其他草稿字段，立即进入该类别下新的未保存行为状态。

## 6. 快捷键与按钮

- `S`：设置或替换开始点，不保存。
- `D`：设置或替换结束点，不保存。
- `Ctrl+Enter`：保存完整行为草稿，与“保存此行为”按钮调用完全相同的统一校验、工作流影响确认和 Annotation API 路径；普通 `Enter` 不保存。
- 数字类别快捷键只更新类别，不清空点位或兼容的参与对象。
- `Esc` 继续优先关闭弹窗、退出参与对象导航或取消已有标注编辑；无更高优先级状态且存在当前新建标注时，可进入与“重置标注”完全相同的确认流程，不得直接清空。
- 输入框、下拉框和可编辑区域聚焦时，不触发标注快捷键。
- 快捷键帮助同步改为“设置开始”“设置结束”，不得继续描述 `D` 为立即提交。

## 7. 重置、切换与离页

- 页面提供次要操作“重置标注”。点击后必须先确认；确认后清空当前新建标注的类别、开始点、结束点、参与对象（含角色分配）、可信度及其他全部草稿字段，不调用后端；取消确认则所有信息原样保留。
- 保存失败、保存前工作流确认被取消、退出参与对象导航均不等于重置标注。
- `Esc` 若在既有优先级处理后进入重置流程，也必须复用上述确认，不得直接清空。
- 同一视频内切换到 track 修正模式时完整保留草稿，不弹离开确认；返回行为标注模式时完整恢复类别、起止点、参与对象、可信度及其他草稿字段。
- 切换上一个/下一个视频、返回视频库或离开当前路由时，若存在草稿，必须确认继续编辑或放弃草稿后离开。
- 草稿不自动保存，也不带入其他视频。
- 浏览器刷新/关闭页面时，如存在草稿，启用浏览器离页保护。

## 8. 帧与时间边界目标

### 8.1 当前缺陷

当前前端统一使用：

```text
frame = round(time × fps)
```

后端媒体层把 `start_frame/end_frame` 视为双端 inclusive，并渲染：

```text
[start_frame / fps, (end_frame + 1) / fps)
```

因此手工结束时间、播放器当前时间和最终片段结束边界可能相差一帧。时间字段目前还允许一帧容差，可能掩盖不一致，而不是建立唯一转换规则。

### 8.2 确认权威模型

采用帧权威模型：

- `start_frame/end_frame` 是行为区间唯一离散权威，双端 inclusive；
- 播放器设置点位时，当前显示帧直接成为对应 frame；
- `start_time = start_frame / fps`；
- `end_time = (end_frame + 1) / fps`，表示 inclusive 结束帧之后的半开时间边界；
- 行为覆盖帧数为 `end_frame - start_frame + 1`；
- 媒体、tracks、Submission 和正式导出全部复用同一转换函数；
- 最后一帧必须 clamp 到 `frame_count - 1`，不得产生 `end_frame == frame_count`；
- 界面时间只读，不提供独立秒输入；不再独立保存未经规范化、可能与帧冲突的播放器浮点时间；
- API、数据库约束、保存校验、Submission 提交重校验和正式导出前验证统一要求 `end_frame > start_frame`；
- API、保存、Submission、媒体、tracks 与正式导出均复用上述帧—时间转换，不得各自换算。

播放器设置点位时只读取当前显示帧；派生时间仅用于展示和媒体半开边界，不反向成为区间权威。

## 9. 已确认交互决策

1. **保存后保留项**：只保留类别；清空开始点、结束点、参与对象（含角色分配）、可信度及其他草稿字段，并开始新的未保存行为状态。
2. **保存快捷键**：采用 `Ctrl+Enter`，与“保存此行为”按钮复用同一统一校验、确认和 API 路径；普通 `Enter` 不保存。
3. **重置标注确认**：每次点击“重置标注”均先确认；确认后清空当前新建标注的全部已选信息，取消确认则原样保留。`Esc` 仅可在既有优先级兼容时进入同一确认，不直接清空。
4. **切到 track 修正**：保留当前视频草稿，返回行为标注模式时完整恢复，不弹离开确认。
5. **结束点展示**：时间轴不显示独立结束点标志；开始点持续显示，起止点齐全时显示草稿区间。仅有结束点时只在草稿摘要中明确结束已设置，时间轴不画结束标志或区间。

## 10. 验收标准

- 类别、开始、结束、参与对象以多种顺序填写，最终 payload 完全一致。
- 设置开始后无需设置其他字段，时间轴立即出现并持续显示准确的开始标志；起止点齐全时显示草稿区间且不显示独立结束点标志；仅有结束点时只在草稿摘要显示结束已设，时间轴不画结束标志或区间。
- `D` 不创建标注；只有点击“保存此行为”或按 `Ctrl+Enter` 才进入完全相同的统一校验、确认和创建 API 路径，普通 `Enter` 不保存。
- 不完整草稿点击保存时一次显示完整错误且保留全部已填信息。
- 保存成功后已保存区间正常展示，草稿只保留类别并开始新的未保存行为状态，起止点、参与对象（含角色分配）、可信度及其他草稿字段均已清空。
- “重置标注”始终先确认；确认后清空当前新建标注全部字段，取消确认时原样保留；`Esc` 不直接清空。
- 保存失败、确认取消、track 导航退出不丢草稿；同一视频切到 track 修正模式时完整保留，返回行为标注模式时完整恢复且不弹离开确认；确认重置或确认离页后才清空。
- API、数据库、保存、Submission 与导出前验证均拒绝 `end_frame <= start_frame`，每条行为至少覆盖两个帧索引。
- 每个所选参与 ID 分别与 inclusive 行为区间内至少一帧未抑制有效检测相交；不要求共同出现、覆盖首尾或达到覆盖率。
- 同/不同类别及同一参与 ID 的多条行为任意重叠均可保存、提交和导出，不触发通用互斥错误。
- 帧边界覆盖 25/30/60 FPS、非整数浮点误差、第一帧和最后一帧。
- 帧始终是唯一权威；保存、Submission、媒体片段、tracks 与正式 ZIP 对同一区间复用同一转换，得到一致的首帧、末帧、帧数及派生半开时间边界。
- 开始标志、草稿区间及摘要中的结束状态满足键盘、屏幕阅读器、非纯颜色和窄屏可辨识要求。

## 11. 当前实现依据

- `frontend/src/pages/AnnotatePage.tsx`：现有 `startPoint`、类别/参与对象状态，`S` 设置起点、`D` 立即保存，切视频保护及全局快捷键。
- `frontend/src/components/Timeline.tsx`：当前只接收已保存区间，没有未保存开始/结束点或草稿区间输入。
- `frontend/src/utils/format.ts`：当前 `timeToFrame` 使用 `Math.round(time * fps)`。
- `backend/app/submission_media_plan.py`：当前 Submission 媒体使用双端 inclusive 帧和半开渲染时间区间。
- `backend/app/submission_service.py`、`backend/app/export_jobs.py`：提交重校验和正式导出需要与同一边界 authority 对齐。
