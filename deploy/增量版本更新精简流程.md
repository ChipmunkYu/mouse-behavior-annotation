# 标注服务器增量版本更新精简流程

> **定位**：仅适用于已经稳定运行的标注服务器增量更新。首次建站、灾难恢复、主机迁移仍查完整的 [`部署复盘与运维指南.md`](部署复盘与运维指南.md)。
>
> **执行约束**：先按实际 diff 判级，再执行被触发的门禁。任何服务器命令（包括只读命令）仍须先逐条展示、说明目的并获得用户明确授权。

## 1. 最近两次发布复盘

| 发布 | 实际变化 | 必要步骤 | 条件触发步骤 | 可裁剪的冗余 |
|---|---|---|---|---|
| `fc749b2` | 代码更新，并更新 `projects/2` 生产类别数据 | 固定 commit 的完整 release；本次相关测试/build；独立 `.venv`、依赖安装与 `pip check`；生产前端 build；当前 schema/业务基线；停止唯一写进程；一致性备份与 `PRAGMA quick_check`；事务 apply；专项 verify；切换、restart、HTTPS health 与最小业务读写 | 检测导入、迁移和部署配置测试由实际 diff 触发；浏览器只验本次类别、快捷键和 Split/Merge 反馈 | 上传脚本 hash（脚本直接从固定 Git release 执行时）；同服务器备份再做 SHA；dry-run fingerprint、后续重复 SQL、最终 hash 多层叠加；停服的 `systemctl`/`ss`/`lsof` 三重证明；不相关系统、端口、工具和公网检查 |
| `85d635a` | 纯前端 track 列表热修，无 DB、后端、依赖和部署配置变化 | 受影响前端 tests、typecheck、本地 build；固定 commit 的自包含 release；服务器端 `npm ci/build`；原子切换；HTTPS 首页、新静态资源和受影响交互 smoke | 独立 backend `.venv`、安装与 `pip check` 是当前 release 结构的固定成本，不因纯前端而省略 | 后端直连 health 与 HTTPS API health 同时执行是重复；创建、切换阶段反复核对 release HEAD/clean；无变化的 DB、Nginx/TLS、公网、上传和全浏览器矩阵 |

`85d635a` 可以在 release 创建完成后核对一次 `HEAD` 与 clean；切换后只核对 `current` 的解析目标，不再重复完整 Git 检查。它不需要停服或 restart。独立 backend `.venv` + install + `pip check` **不是冗余**：systemd 从 `current/backend/.venv` 启动，未来任何重启都必须可用。纯前端 release 仍须自包含。服务器端 `npm ci/build` 用于生成该 release 的生产产物，本地 build 是提交前门禁，两者目的不同。

`fc749b2` 中 `projects/2` 的备份、事务、基线保护和最终 verify 必须保留。数据库最小证据固定为：当前 schema/业务基线一次，停止唯一写进程一次，一致性备份加 `PRAGMA quick_check` 一次，事务 migrate/apply，专项 verify 一次。数据回滚不能只切代码。

## 2. 不再默认执行的过度防御检查

以下项目只有被 diff 或故障触发时才执行，不随每版机械重复：

- 每版重新盘点整机、端口、磁盘和全部工具。
- 不相关的全量测试和真实 FFmpeg 验收。
- 同一阶段多次完整核对 SHA、Git HEAD 和 clean；Git 内文件逐个计算 hash。
- 上传到同服务器后再校验固定 Git release 内脚本的 hash；同服务器数据库备份再做 SHA。
- 停服后同时用 `systemctl`、`ss`、`lsof` 三重证明；停服前后重复查 active jobs/dirty state。
- 无 DB 变更却检查 schema、integrity 或创建备份。
- 数据脚本已有基线门禁、事务和专项 verify 后，再叠加人工重复 SQL、fingerprint、文件 hash。
- 无条件同时跑后端直连 health、本机 HTTPS health、公网 health；正常 L2/L3 只保留一个本机 HTTPS health，直连和 journal 留作失败诊断。
- 无 Nginx、TLS、DNS、安全组或网络入口变化，却复查证书、公网和上传矩阵。
- 每版执行浏览器全矩阵；默认只验受影响交互。

裁剪的是重复证明，不是安全边界。输入校验、事务、一致性备份、secret 保护、鉴权和明确由 diff 触发的测试不得省略。

## 3. 按 diff 分级

| 级别 | 范围 |
|---|---|
| L0 | 文档-only |
| L1 | 纯前端代码或静态资源 |
| L2 | 后端、API 或依赖变化，但无 DB 变化 |
| L3 | migration 或生产数据变更 |
| L4 | Nginx、systemd、secret、TLS、DNS、安全组或其他网络入口变化 |

混合变更组合所有被触发的门禁，不机械执行未触发级别的全套流程。例如“前端 + 生产数据”组合 L1 与 L3；“后端 + Nginx”组合 L2 与对应 L4 门禁。

### 当前 release 的结构性成本

当前所有会切换 `current` 的 L1–L4 release 都必须自包含：

1. 检出固定 commit，创建后核对一次 `HEAD` 与 clean。
2. 在 release 内创建独立可用的 `backend/.venv`，安装锁定依赖并运行 `pip check`。
3. 在 release 内执行前端 `npm ci`、`npm run build`，确认 `dist` 产物。

这是当前 `current` 同时承载前端静态目录和 systemd 后端工作目录的结构性成本，不是检查偏好。只有未来改为独立 frontend/backend release 后才可重新裁剪；本轮不改架构。

## 4. 各级最小流程

### L0：文档-only

- **本地门禁**：检查目标 diff、Markdown 结构、相对链接与 `git diff --check`。
- **release / 服务 / DB**：不创建 release，不停服、不 restart、不查 DB。
- **smoke**：无需线上 smoke。
- **回滚**：恢复文档提交即可。

### L1：纯前端

- **本地门禁**：受影响 tests、typecheck、本地 production build。
- **release**：创建完整自包含 release；创建后只核对一次 `HEAD`/clean。
- **服务 / DB**：不停服、不 restart、不查 DB；原子切换 `current`，随后只核对其目标。
- **最小 smoke**：HTTPS 首页、本版新静态资源和受影响交互；API health 非必需。
- **回滚**：将 `current` 原子切回上一已验证 release；通常无需 restart。

### L2：后端、API或依赖，无 DB

- **本地门禁**：受影响后端与安全测试；前后端契约变化时增加契约检查，依赖变化时验证锁定结果。
- **release**：创建完整自包含 release。
- **服务 / DB**：不查 DB；原子切换后 restart 后端。
- **最小 smoke**：一个本机 HTTPS health，加一个受影响 API；后端直连 health 和 journal 仅在失败时诊断。
- **回滚**：切回上一 release 并 restart；复测相同 health/API。

### L3：migration或生产数据

- **本地门禁**：迁移或数据脚本的聚焦验证，覆盖基线拒绝、事务回滚和专项 verify。
- **release**：在停机前完成完整自包含 release，不把安装或 build 放进停机窗口。
- **停服前**：只查当前 schema、与本次有关的业务基线和运行任务；不查无关 dirty state。
- **DB**：停止唯一写进程一次，不再用 `ss`/`lsof` 重复证明；创建 SQLite 一致性备份并对备份执行一次 `PRAGMA quick_check`；在事务中 migrate/apply；执行一次专项 verify。
- **上线与 smoke**：原子切换、restart；执行一个本机 HTTPS health 和最小变更读写验证。
- **回滚**：代码与数据分别规划。数据不兼容或 apply 已改变业务数据时，不能只切代码，须使用对应逆向方案或已验证备份。

### L4：部署与入口配置

- **本地门禁**：只执行实际变化对应的配置测试，不自动扩大到所有基础设施。
- **release**：凡切换 `current` 仍创建完整自包含 release；仅更新外置配置且不切换时按该配置的部署方式执行。
- **应用**：Nginx 变化先 `nginx -t`，通过后 reload；systemd unit 或后端运行环境变化后 daemon-reload（如需要）并 restart；secret 只安全注入，绝不输出内容。
- **最小 smoke**：验证改变的入口。只有 DNS、TLS、安全组或公网路由变化时才做公网 smoke；上传、鉴权等矩阵只验本次受影响路径。
- **回滚**：恢复上一已验证配置/secret 引用；再次通过对应配置检查后 reload 或 restart。

## 5. 自动升级触发器

出现下列任一项，必须在基础级别上追加对应门禁；影响面无法圈定时扩大验证，而不是猜测安全：

- 依赖或运行时版本变化。
- migration、schema 或生产数据变化。
- auth、权限、上传、删除或导出路径变化。
- 后台任务、并发、锁、队列或单 worker 假设变化。
- FFmpeg/ffprobe、媒体处理参数或产物契约变化。
- `deploy/`、Nginx、systemd、secret、TLS、DNS、安全组或网络入口变化。
- 前后端 API 契约变化。
- diff 影响面无法圈定。
- focused 测试失败、偶发失败或结果不稳定。

## 6. 失败停止点

- 本地门禁失败：不创建或不继续使用候选 release。
- release 的 commit、clean、自包含依赖或 build 不成立：不切换 `current`。
- 停服后发现相关任务仍运行、DB 基线不符、备份或 `quick_check` 失败：不 apply、不切换。
- migrate/apply 或专项 verify 失败：保持服务停止，按专项数据回滚方案处理，不用后续 smoke 掩盖失败。
- `nginx -t` 失败：不 reload；restart 后 readiness 失败：停止重复 restart，转查直连 health 和 journal。
- 最小 smoke 失败：停止扩大验收，先回滚或修复最小失败路径。

## 7. 最小发布记录

每次只记录能够复现和回滚所需字段：

- 日期、操作者、变更级别及触发器。
- 目标完整 commit、上一 release、`current` 最终目标。
- 本地门禁与候选构建结果。
- 是否停服/restart/reload，是否涉及 DB。
- DB 变更时的变更前 schema/业务基线、备份路径、`quick_check`、apply/migrate 和专项 verify 结果。
- 最小 smoke 结果、已知未验范围、回滚目标与数据回滚方式。

不要在记录中写 secret、完整环境变量、token、私钥或无关命令输出。

## 8. 默认执行算法（Agent checklist）

1. 读取本文件和目标 diff，判定 L0–L4；混合变更合并触发项。
2. 检查自动升级触发器，只运行受影响门禁；不先套完整 15 步流程。
3. 列出最短命令批次、成功证据、失败停止点与回滚目标。
4. 对每条必要服务器命令先请求用户授权；未经授权不执行。
5. 完成候选后再切换；按级别决定停服、DB、restart/reload 和最小 smoke。
6. 写入最小发布记录；失败时记录停在哪一层，不补跑无关检查。

本流程不建议引入新框架、脚本、CI 或架构重构；现有命令和项目测试足以完成日常增量发布。
